# jawata-studio v4.4.10

**The tray opens with what you do most, the Seats view should scroll faster, and an IntelliJ project can be imported as a workspace.**

## What went wrong

- **The tray menu put its status line above Open dashboard,** although opening the dashboard is what you do most, and the versions sat at the bottom beside Quit.
- **The Seats view scrolled slowly in the installed window:** each of its 18 cards draws a soft shadow that is redrawn on every scroll step.
- **An IntelliJ project could not be added as a workspace:** the import took VS Code `.code-workspace` files and folders with a Maven, Gradle or Eclipse build only.

## What changes

- **Tray order:** Open dashboard first, then the studio and engine versions, then the health line (for example "3 of 3 residents healthy"), then the workspaces, the start/reload/stop actions, Autostart and Quit.
- **Seats scroll:** cards inside a scrolling view draw no shadow. This is a candidate fix: the cause was not measured, so your scroll in the installed window decides whether it worked.
- **IntelliJ projects:** in the import that took `.code-workspace` files, pick an IntelliJ project folder or its `.idea/modules.xml`, and the studio offers each module of its module list. A module with a Maven or Gradle build becomes a project; a module without one becomes a project when its `.iml` names a source folder that exists. A module file the studio cannot read is reported by name. The import section takes either kind.

## Known limits

- **The source folders an IntelliJ module declares are written into `workspace.json` but not read by the engine yet;** a later engine release will read them. Until then such a module loads the way any folder without a build file does.
- **The Seats scroll change is unmeasured** (see above).
- **The changed import screen has no rendered screenshot;** it was checked from its source.

Works with jawata-mcp 4.4.15.
