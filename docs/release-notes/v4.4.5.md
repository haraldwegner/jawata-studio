# jawata-studio v4.4.5

**Autocontinue is switched by two typed commands and by nothing else, and the rottenmeier seat proposes rules for him to accept.**

## What went wrong

- **Autocontinue was switched off by messages he never typed.** The hook cannot see the chat window. Claude Code runs the prompt hook for a scheduled task, a subagent reporting back and a message from another session, and the hook's input carries no field saying where the text came from. The transcript cannot tell either: measured on 2026-10-18, a Chrome extension's injected instruction and his typed message carried the same `turnOrigin`, `origin` and `promptSource`. So "any message of his ends the grant" switched it off for text he did not type, and ten releases that tried to infer the channel from the text each shipped blind to the next channel.
- **The check on undescribed members asked about whole files.** A one-line edit to a class of twenty tests demanded twenty-three descriptions, about 25 tool calls and a store row each.
- **A seat that writes only the knowledge store could not run as a hire.** Plan mode refuses the engine's `experience` tool for every kind, reads included.

## What changes

- **`/autocontinue` switches it on and `/autocontinue-off` switches it off.** Both are skills the studio deploys like `/btw`. The grant changes only when the prompt is exactly one of the two lines. A typed question, any other typed message, a message from another session, a subagent's report, a scheduled task and an extension's injected text all leave it where it was. An agent cannot switch it: the guard refuses a Skill call naming either command, and the hook's mode line states the rule.
- **This replaces two rules.** A typed message of his no longer ends the grant, and saying "autocontinue" at the end of a message no longer arms it. What Esc does is unchanged, and so is the rule that a showstopper, a complete redesign or a release reaching him ends it.
- **The stop check names the lines a turn wrote.** The hook keeps the new text of each Java `Edit` and finds the lines it occupies in the file as it now stands; the engine asks only about the methods those lines fall in. A `Write`, a text that is no longer in the file or found in more than eight places, or an empty text, asks about the whole file as before.
- **The rottenmeier seat** reads his reactions in the transcript lane, names what the agent did wrong and proposes a rule as a candidate for him to accept; a rule names who it binds (`seat:<name>`, an activity such as `release`, or `all`) and when it applies. It is a deployed `/rottenmeier` command. The `pm` seat carries the `release` activity. The hook's lane table has the row for a typed message: experience and rules.
- **A seat can declare `writes_store: true`** and is then hired outside plan mode, still with every code-changing tool hidden and none of the CLI's own file tools offered. The studio reads the key as strictly as the engine. The rottenmeier and cataloguer seats declare it. The first real rottenmeier hire without it read none of his turns and wrote no rule; with it, on his 185 corrections, it saved 7 candidate rules, all unaccepted.

## Known limits

- **The two commands were tested against the real records of 2026-10-18 and have not yet been exercised on an installed copy.** The live check waits for this release to be installed.
- **The stop check's narrowing needs engine 4.4.10.** Against an older engine the hook's extra field is ignored and the whole file is asked about.
- **Seven other seats that declare `experience` still run in plan mode** and are inferred to be blind to the store there; only rottenmeier and cataloguer were measured and changed.
- **The seven rules the rottenmeier seat proposed were traced to his words alone,** because the transcript lane holds no agent replies. None is accepted.

Works with jawata-mcp 4.4.10.
