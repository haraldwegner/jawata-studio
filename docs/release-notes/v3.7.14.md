# jawata-studio v3.7.14

Claude Code's hook folder gets cleaned up too.

v3.7.11 taught a deploy to leave the live programs and remove our own leftovers.
That cleanup was added to the Cursor deploy and not the Claude Code one, so
`~/.claude/jawata-studio/` kept the misnamed binaries v3.7.9 had written —
sitting beside the correct ones, unusable, and invisible to every test.

Both deploys now clean up, because the cleanup moved *into* the step that writes
the programs. A directory's contents are that step's business, so the two paths
can no longer disagree about it — which is what went wrong, twice.

Your own hooks, the configuration and the log are untouched: only files carrying
jawata's own prefix are considered, and the live ones are kept by name.

## Known, and not fixed here

On Windows the guard is not yet blocking. It is deployed, correctly named and
configured, and a shell command that should be refused still runs. That is the
next thing being chased; this release does not claim to fix it.
