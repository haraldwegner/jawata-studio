# jawata-studio v3.12.3 — the message gate stops arguing with itself

A bug-fix release. Everything here was found by running v3.12.2 for an
afternoon and watching what it actually did.

## The gate was erasing its own evidence

The stop gate asks for one thing: that a message be reviewed before it is
sent. It kept asking after the review had happened.

Claude Code injects a blocked stop's reason back into the session as a **user
turn**, and the gate resets its window whenever the user speaks — so the
review that happened *before* the bounce was gone from the window the retry
judged. Complying could not satisfy it. It asked again, every turn.

The bounce is now recognised as the client echoing our own decision rather
than as the human speaking. It is matched on the client's wrapper at the start
of the line, deliberately not on our own rule text, because the human quotes
that text back in conversation and matching it would let a real message be
mistaken for a bounce.

## The retry no longer excuses a missing review

The anti-loop valve returned "allow" for everything once a pass was marked as
a retry, so every rule was a single nag: block once, and doing nothing walked
past it. Measured: blocked at 15:53:52, allowed 0.8 seconds later.

Now exactly one thing may still hold a retry — the missing review — and only
up to three bounces, after which the turn passes and the giving-up is
recorded. Bounded rather than surrendered: the concern the old valve existed
for is real, and a gate that can hold forever wedges a session.

## A continued reviewer counts as a review

The reviewer is meant to be **one per session, continued** rather than
respawned. It only ever sees the user's messages and the agent's drafts, so
what it accumulates is exactly what the user has — it stays level with the
reader instead of behind them, and a genuinely cold reviewer would demand
terms re-explained that the reader already owns.

The gate could not see that. It matched a fresh spawn only, so continuing the
reviewer did not count and the rule would have demanded a new one every turn —
punishing the design in the name of a rule already satisfied.

## Known, and not fixed here

**#23 remains open.** These changes route around the stale-turn defect; they
do not repair it. The rules that must read the final message — too long, asks
for a decision, undefined terms — stay dead until the gate can read the
message it judges.
