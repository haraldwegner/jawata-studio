# jawata-studio v4.6.3

**The chat answers directly, Deploy removes Red Hat's Java extension and serves every VS Code build, and Seats finds agents installed with npm.**

This release needs jawata-mcp 4.6.5 (4.6.4 was never published) and the jawata chat and jawata Java extensions 0.2.3, which Deploy installs.

## What you see

- **The chat answers what you asked.** The studio no longer starts a second brain to review every answer; with engine 4.6.5 "Who are you?" gets an answer, first word after about 6 to 9 s in a new chat (it took 43 to 57 s and returned no answer). Main, the project manager and the chief engineer are told to put a hire's result into their reader's terms themselves.
- **Deploy removes Red Hat's Java extension** and every extension that needs it or came in a pack with it, and says each one by name. jawata Java brings the Java language support, the Testing view and the debugger. Its result on the dashboard is two lines: the editor extensions installed or removed, and the jawata servers set up for each agent.
- **Deploy serves VSCodium and Code-OSS too.** It installs through each editor's own command (`code`, `codium`, `code-oss`) and names the folder each one installed into.
- **Seats finds an agent program installed with npm under nvm** (or another npm folder) after you reopen the tab, with no restart, and the engine starts it with that folder on its path.
- **The main seat's default model is chosen in Seats** from the models that brain's own session offers.
- **The Workflow view fills the window when first opened**, with two lines saying what it shows and how to change it, and heavier boxes.

## Known limits

- On a real VS Code and a real VSCodium (Linux, in a scratch home) the deploy removed Red Hat's extension and installed both extensions; the dashboard's two lines, the Workflow view and the Seats models were checked in tests and renders, not in the installed studio window.
- The first answer of a chat carries the main seat's text, which takes the brain about 5 s to read; later answers do not.
- Checked on Linux. Windows and macOS builds are produced but were not used by hand.
