# jawata-studio v4.2.4

Starting up stops looking like something being wrong.

## Amber no longer appears every time a workspace starts

Switching workspaces on showed amber — *something is wrong* — for several seconds in the
middle of every start-up. Nothing was wrong. They were starting.

**The cause is that the tray was asking a question that cannot answer this.** A workspace
service is reported as "starting" for two seconds after launch and as "running" from then
on, whether it is actually ready or not — a shortcut that exists for test stand-ins which
never announce themselves, and which applied to the real thing as well. A real workspace
service takes five to ten seconds to announce it is ready, so for most of its start-up it
was reported as running while it could not yet answer anything.

*Running but not answering* is exactly what broken looks like. So the tray was reading a
true signal about a false premise.

It now asks whether the service has actually announced itself, which is the only thing that
separates one on its way up from one that has failed. A workspace that has not announced
itself yet is shown as starting, and one that never does stays shown as starting rather than
being called broken once a timer runs out.

**Something genuinely broken is still amber**, including while another workspace is fine.
That is not a promise in prose — the same unanswerable workspace counts as a fault without
the new signal and as a start-up with it, so the two halves are proved by the same pair of
checks.

## Switching everything on no longer leaves the icon blue

The icon stayed on *nothing running* well after switching workspaces on.

The repaint happened only when a start or stop was announced — and that announcement is made
the moment a start is **requested**, before the state it reads has been recorded. So it drew
the previous answer, and nothing repainted afterwards to correct it.

The tray now refreshes on every cycle. It costs nothing: it asks no workspace anything, and
an unchanged verdict is not redrawn.

## The dashboard stops calling a mixed workspace a problem

The same mistake, on the other surface. "Managed Projects" showed an amber **MIXED**
badge whenever some workspaces were running and others were not — because anything other
than all-running or all-stopped was collapsed into *starting*, which is painted amber.
Two running and one deliberately stopped is neither starting nor wrong.

Partly running is now its own state, in the dashboard's version of the tray's vocabulary:
a **green ring around a grey centre**. All running stays solid green, nothing running is
grey, and amber is kept for something actually being wrong.

The badge also stops saying "mixed" and says **"2 of 3 running"**. "Mixed" reported that
the states differ and nothing about which way, so the reader had to go and count — and the
numbers were already on screen.

The workspace list carried an identical collapse and is fixed with it.

## The sequence you should now see

Switch everything on: **blue** → **grey** while they start → **green ring on grey** as the
first one becomes ready → **dark green** when they all are. Switch one off: **green ring on
blue**, within a second.

Both fixes came from using v4.2.3 rather than from a test.
