# jawata-studio v4.6.12

**Each editor window keeps its own list of folders for the engine, the seats build test first, and the commit hooks refuse the same agent names.** This release needs jawata-mcp 4.6.10.

## What changes

- **One list of folders per editor window.** A window names itself (`--editor-window`), and the studio keeps that window's list; a window that hands over no folder is forgotten. Launches from one window are numbered as they arrive, and only the latest writes or clears its list, so a slow scan or a close during it cannot bring an old list back. The jawata guard reads these lists and the loaded projects' folders on every call, so a folder a window opens after a hired agent started is reachable, and one it closes is not.
- **A window's process is told from another by its identity,** not by a number that may have been given to a different process: the boot id and start count on Linux, the start time `ps` reports on macOS, the process number on the BSDs.
- **Seats.** A new behaviour is built test first by the developer; the chief engineer and the project manager issue it as a BUILD instruction with test sentences and no code. The developer may write the empty stub a test needs where no jawata tool adds the method (`generate(kind=add_method)` first). The main seat, the project manager and the chief engineer may write documents, data and pictures and edit no code. The observer answers by the point number of each flagged step.
- **The commit hooks refuse the same agent names the engine refuses.** The commit-msg hook matches an agent name anywhere in a co-author line and refuses `[bot]`; the pre-commit hook adds `gemini` and `codex`; a self-test in `run-gates` drives the hook.
- **Planning is named by the workspace's planning folder** in the sprint rule, the architect's findings path and the stop judge, not by `docs/sprints/<product>/` and `~/.claude/plans`.

## Known limits

- The folder lists and the guard are covered by tests. The studio was not shown in a real editor window for these changes, and Windows and macOS are run by CI, not by hand.
- The planning folder per workspace, and adopting a workspace as the first workflow step, are not built; this release only stops naming the old places.
