# jawata-studio v3.7.9

Cursor on Windows: all four hooks, no shell anywhere.

v3.7.8 moved one of Cursor's four hooks — the guard — to the native binary,
because that was the one whose failure blocked commands. The other three stayed
shell scripts, and Windows cannot execute a `.sh`. Worse than inert: Cursor
tried to open each one, so a window appeared at session start, on every prompt
submitted, and after every tool call. Reported from a Windows 11 machine as
"it does not work on windows because it still tries bash", which was the correct
reading — the cutover was half done.

All four now run as the binary, and the scripts they replace are deleted from
existing installs on the next deploy. On Windows that turns Cursor from
guard-only into the full set: session-start context, prompt-submit recall, the
guard, and the after-tool seam.

The observer needed a decision rather than a port. Its Claude Code script
captures tool outcomes and the fallback audit trail, so cutting *that* one over
would lose them — it stays a script there, as before. Cursor's observer script
loses nothing, because it does nothing: its entire body reads its input to
`/dev/null` and prints an empty object. Two generations that both do nothing are
not a parity question, so Cursor's cuts over while Claude Code's does not. The
per-client difference is declared in `hook-events.json` with its reasoning, and
a test fails if the code and that declaration ever disagree.

Also corrected: the v3.7.8 release notes claimed the whole Cursor cutover had
shipped when only the guard had. The published text now states what shipped and
what did not.
