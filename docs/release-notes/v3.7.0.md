# jawata-studio v3.7.0 — Prove the engine

Sprint 28. Ships against jawata-mcp v3.7.0.

## The ten hook scripts are one binary

The per-client hooks were ten generated bash scripts that parsed JSON with
regexes — which is why one of them injected nothing for two weeks while every
test stayed green: a payload whose shape moved slightly still "matched" and
produced an empty cue, and an empty cue is indistinguishable from "nothing to
say".

`jawata-hook` is now a single Rust binary, shipped as a packaged sidecar on all
five targets, dispatching on its own name. It cannot depend on the studio and
the studio cannot depend on it; both edges are asserted by tests.

## Silence is explainable

The hook records WHY it stayed quiet — one line per invocation, with a stable
tag per reason. A timeout records itself before the watchdog ends the process,
which was the one silence the log could not previously explain.

The reason taxonomy is declared once and generates its own enum, tags and test
specimens, so a new reason cannot exist without being forced by a test.

## An upward ask must be judged before it is sent

The stop gate blocks a message that asks for a decision when no communicator
pass ran since the human's last turn, and blocks an audit-fix loop that never
reaches a checkpoint — the state in which the previous gate could never fire,
because every trigger it had was a checkpoint marker.

It reads the tail of the transcript rather than all of it: 3,021 ms per turn
became 34 ms on a 332 MB session.

## Install and upgrade

An install carrying the old script entries converges to one managed entry per
event. The user's own hook entries are preserved across every generation.

## Fixes

- macOS: the sidecar is signed, notarized and stapled with the app.
- Windows: both the `.msi` and the NSIS installer are verified to contain the
  hook — the `.msi` previously shipped asserted by nothing.
- Linux: the AppImage payload is verified after the repack that patches it.
