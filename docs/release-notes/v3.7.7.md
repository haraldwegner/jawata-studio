# jawata-studio v3.7.7

Seat definitions stop going stale — an update now actually updates them.

The seat roles (`/refactor`, `/debug`, `/cover` and the rest) are generated
from copies placed in your config directory, kept editable so your own
changes survive. Until now those copies were written once and never touched
again: an improved seat shipped in an update existed in the app and never
reached the deployed role, on every machine, forever — found when a
freshly-shipped improvement was absent from the very machine that shipped it.

Now the deploy remembers what it wrote. A copy you never edited refreshes
automatically whenever an update ships newer content. A copy you edited is
preserved — and the deploy result names it, so a newer version shipping past
your edit is a visible fact instead of a silent one. Installs from before
this release adopt matching files as-is; a differing file is refreshed with
the old content kept beside it as `*.pre-refresh` — nothing is destroyed,
and nothing stays silently stale.
