# jawata-studio v4.6.1

**What the first use of 4.6.0 found: a readable Workflow chart, one Java Projects view, install messages for missing agents, Copilot as a chat brain, and a model on the chat rows.**

This release needs jawata-mcp 4.6.1 and the jawata chat and jawata Java extensions 0.2.1, which Deploy installs.

## What you see

- **The Workflow chart's lines are 2 pixels in the text colour, and the chart is sized to the window.** Shown in a browser render of the page at three window sizes; not yet looked at in the real studio window, where the move of a seat and the refused move snapping back are also not yet shown.
- **"Deploy to agents" is built to remove Microsoft's Project Manager for Java** once jawata Java is installed, so that Java Projects shows once, and the result names it. Covered by a test of the deploy code; a real deploy through the studio on a machine that has it has not been run.
- **The Seats page is built to name each agent the chat cannot use yet and the command that installs it** (Claude Code, Codex, Copilot), read from the same list that decides what is offered. Nothing is downloaded. Covered by tests; not yet looked at in the real window, and installing an agent and finding it without a restart was not run.
- **Copilot is a brain for the chat and the side discussion**, started with `--acp` and with the jawata servers deployed to it switched off for that start, because three of them did not fit its context.
- **The principal's Cursor runs on grok-4.5** when the account has it, and the chat rows name it; the setting is the principal's alone, hired agents keep Cursor's default.
- **`/setup` is told to start a new project** in an empty folder, prove its green command by running it, and write `jawata-project.md`. The skill's text is tested; `/setup` has not been run in an empty folder.
- **`/sprint` is told to keep one folder per sprint**, with the plan inside it and the raw committed before it is deleted. The rule is written into the skill; no `/sprint` run has been shown and no existing sprint has been moved.

## Known limits

- Run, Debug and the test buttons in VS Code still need Red Hat's Java extension: with jawata Java and no Red Hat none of them works (measured). jawata's own come in the next VS Code stage, so Deploy keeps leaving Red Hat in place and says why.
- Copilot as the principal answers slowly (about a minute for a greeting here), because each turn carries the engine's tool definitions.
- The studio uses its own `PATH` to find agent programs, so an adapter installed in a folder the studio was not started with is not seen until the studio is restarted from there.
- Checked on Linux. Windows and macOS builds are produced but were not used by hand.
