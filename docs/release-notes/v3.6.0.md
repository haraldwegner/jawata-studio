# JAWATA Studio v3.6.0

Sprint 28 (client + OS coverage) opens here. A macOS retest found that on that
machine the runtime could not be updated at all, one deploy target could never
be selected, and the menu-bar icon was absent. All three are fixed.

Ships alongside **jawata v3.6.0**, which recovers the build path on Eclipse
plug-in projects.

## The runtime update could not complete

The update failed with `failed to read JAWATA archive bytes: error decoding
response body`, and the machine stayed pinned on an old runtime while Studio
kept offering an update it could never finish.

It was not a macOS problem and not a broken download link. One HTTP client
served both the small "what is the latest release" request and the 107 MB
runtime archive, under a single 10-second budget that covers the entire
transfer. Completing in time required a sustained 10.7 MB/s from first byte to
last, so on any ordinary connection the transfer was cut off part-way through
and the partial result reported as a decoding failure.

The archive download now has its own budget, sized to the archive instead of to
a small text request, and is written straight to disk rather than held whole in
memory. A download that genuinely fails now says what went wrong instead of the
single unhelpful line above.

**This affected everyone on a managed runtime, not only macOS.** If Studio has
been offering you an update that never lands, this is why.

## Claude Desktop could never be deployed

Ticking **Claude Desktop** in the deploy targets and running a deploy reported
*"Skipped: not selected in this deploy run"* — the deploy telling you that you
had not selected something you had just selected.

The window and the deploy engine spelled the client's name differently, so it
was discarded before the deploy step, and nothing checked. Claude Desktop now
deploys.

Two further changes came out of it:

- **An unrecognised client name is now a visible error** that names the
  offending value, instead of being dropped in silence. A deploy can no longer
  claim you skipped something it never understood.
- **The deploy-target checkboxes were rebuilt** so the tick you see and the
  setting that gets stored cannot drift apart.

Every other client was unaffected — their names are single words, spelled the
same on both sides, which is exactly why this went unnoticed for so long.

## The macOS menu-bar icon

The Studio icon was missing from the macOS menu bar. macOS draws menu-bar icons
from an outline and applies its own colour so they suit a light or dark bar;
Studio was handing it a solid dark blue disc, which on a dark menu bar is
nothing to look at. macOS now receives an outline version of the mark; Linux and
Windows keep the coloured badge.

**Please confirm this one on your Mac.** It was reasoned from how macOS draws
these icons and is covered by tests, but it was not reproduced on a Mac here. If
the icon is still absent, the next thing to rule out is menu-bar crowding —
notched MacBooks hide items when the bar runs out of room, which would need the
same fix plus more space.

## Verification

241 tests pass. Six new tests cover the fixes above.
