# v3.17.1 — the autocontinue grant is his, and only his

Fourth fix in the same family, and the first one aimed at the right thing. The three
before it repaired instances; this one removes the power that made an instance
matter.

Reported as *"Why the fuck do you tell but do fucking not autocontinue? This is
fucking still broken after the fourth attempt to solve"* — after a checkpoint report
that said, in its own words, that it was continuing.

## What actually happened, to the second

```
16:30:08Z  the agent posts a checkpoint summary and says it is continuing
16:30:10Z  outcomes.log: autonomy-ended — "his answer is needed"   <- grant DELETED
16:30:10Z  hook_silence.log: stop-allowed                          <- no push
           ... the session sleeps for 21 minutes ...
16:51:58Z  he types the word again, by hand
```

The summary contained one sentence: *"Nothing needed from you — say the word only if
you want one back."* `SAY THE WORD` is entry 18 of a 42-phrase list, matched as a raw
substring. A sentence whose literal content is **nothing needed from you** was
classified as a request for a ruling.

That flipped two switches at once. It stood the push down for the turn, and it
**deleted the grant** — so the session was dead until he retyped the word, and
nothing told him it had happened.

**The mechanism was never asleep.** It pushed 12 times that day and 57 times
all-time. At 16:30 it evaluated the case and declined.

## The safeguard was the trigger

The design already knew about this failure. The grant-kill was gated on the message
having *survived review*, and the code comment says so: an unjudged ask is bounced to
the reviewer with the grant intact, and *"either comes back real (grant ends,
correctly) or dissolves (the work continues, correctly)."*

**The dissolve path did not exist.** The predicate checked whether a reviewer had
been *launched*, never what it *concluded*. On that very message the reviewer
answered *"this report is a progress note inside a run he told you not to pause, not
a request for a decision"* — and the grant died anyway, because running the reviewer
is what completed the condition. The length gate bounced the message to review, and
that bounce is precisely what armed the kill.

## The ruling

> *"You cannot by yourself change the autocontinue variable by yourself. Only the
> conditions met is a way to stop your work. … If I want you to stop at checkpoint I
> don't say autocontinue. But you cannot on your own discretion just switch this."*

The control lives entirely at grant time and it is his: he withholds the word when he
wants checkpoint stops. Stopping and revoking are different powers, and only the
second was ever his to give.

## What changed

- **Only Esc ends the grant.** The agent's own text can no longer revoke it. The
  inferred-ask branch is gone from the clear.
- **The push stands down on a DECLARATION, not a guess.** A `DECISION:` line of its
  own — the form the upward contract already mandates — is now the only thing that
  stops the push. The 42-phrase list still runs, and still costs a message review,
  which is cheap; it no longer stops any work. Every stop reason he named — a design
  or spec direction, access only he has, something genuinely broken, an unresolved
  dispute with the auditor, a release, the sprint finished — is raised *as* a
  decision, so one marker carries all of them.
- **A second bound, for the loop the first cannot see.** *"We need to avoid endless
  loops."* The only ceiling in the hook counts turns that did **nothing**, and every
  round of repair-then-re-review does real work — so a review that will not converge
  reset it forever. There is now a review-round ceiling: three rounds is the rule,
  four is the hard ceiling, and the gap is the blocking exception his `/sprint` rule
  already describes. At the ceiling the gate pushes once more and instructs the agent
  to state the dispute as a decision, so the loop ends visibly rather than by a
  counter running out in the dark.

## What could not be built, stated rather than implied

The gate **cannot recognise an audit round**. It reads seat commands from his own
messages, so a fresh-context auditor the agent spawns for itself is invisible to it.
The ceiling therefore counts subagent spawns — coarse, but real. Ordinary
implementation work spawns none; a review loop spawns one per round. A counter built
on a signal that is not there is what the previous three fixes were.

The message reviewer is carved out of that count. It is a subagent spawn like any
other and runs once per judged message, so counting it would have spent the ceiling
on four reviewed messages in a single ordinary conversation — caught before it
shipped, by his question about what the deviation actually cost.

## Verification

Two regression tests named for the incident. A heuristic ask no longer stands the
push down — the assertion that used to expect the opposite is changed deliberately,
with the reason in the test. A declared `DECISION:` line still does, so the agent
keeps a way to halt and simply has to say so on purpose.

The review ceiling has three: below the cap the ordinary push runs; at the cap the
gate blocks with a message naming the way out; a declared decision at the cap ends
the loop. Its proof-of-life asserts the other ceiling is at zero in that case — if it
could reach it, the new one would prove nothing.

Rust workspace: 24 suites, zero failures. Hook suite: 264 tests, zero failures.
