# jawata-studio v4.4.17

**The hook no longer posts a call the engine refuses on every edit, and whether a service is live is now sent by the backend instead of being worked out twice. Nothing you see in the window changes.**

## What went wrong

- **The hook posted a call the engine retired.** After each source-file edit the hook held the edited text until the next compile or test result and then posted it to the engine as `experience(kind=observe_edit)`. The engine removed that kind in v3.3.1, so every post was refused and counted as a failure: 32 in 0.3 seconds in one day's failure recording. The user saw nothing; the failure counts were noise.
- **The rule "a workspace is live when it is running or starting" was written in Rust at five places and, since 4.4.16, once on the screens.** The two languages were held together only by a text search in a gate.
- **The 4.4.16 release commit contained a symbolic link named `node_modules`** that pointed at a folder on the machine that built it. It broke nothing in the build, but it does not belong in the repository.

## What changes

- **The hook no longer holds edits and no longer posts `observe_edit`,** in the hook program and in the observer script it deploys. A test fails if the hook keeps an edit for a label, and one if the script names the retired kind.
- **`RuntimePhase::is_live` is the one place the rule is written.** Each status record now carries a `live` field beside `phase`, written from the same value at the moment it is sent, so it cannot be staler than the phase. The project list and the workspace list read `live`; the module `workspaceLive.ts` is gone. A test fails if the backend writes the pair of phases out a second time, and the gate that fails when a screen spells it out stays.
- **The `node_modules` link is removed from the repository,** and the ignore file now matches a link of that name.

## Known limits

- **The workspace's summary phase (the tray and the group header) is still worked out from the member phases** in `aggregate_workspace_phase`; it answers a different question (is every project running) and is not the live rule.

Works with jawata-mcp 4.4.18 and 4.4.19.
