# jawata-studio v3.7.6

The Sprint 28 outcome audit's client-side findings, closed — the release now
proves what it ships, across both products.

- **The cross-product seam is tested for real.** Until now the seam test drove
  the hook against a recorded store answer, so a change on the store's side
  could never fail it. The release now boots the *published* jawata store,
  seeds it, fires a real prompt through the freshly built hook binary, and
  fails unless the answer arrives as injectable context. Proven red with a
  broken consumer before it was trusted green.

- **The studio's own test suite gates releases.** Its 280+ tests — every
  deploy proof, every migration, the contract assertions — ran in no workflow
  until now; a release could have shipped with all of them red.

- **The hook contract stops overclaiming.** The per-role generation
  declaration is now asserted from both sides of the seam: the hook binary
  checks every declared role resolves in its own dispatch table, the deploy
  checks its live/retired lists against the same rows, the stop-gate rules
  declared present in the script generation are pinned to the script's actual
  text, and the Cursor deploy is asserted script-only by construction.

- The sprint-process rules gain the missing pieces the audit found: a changed
  contract needs one test driving both sides together that fails when either
  moves, and the architect seat must derive producers, verify both sides, and
  say whether the other side has to change.
