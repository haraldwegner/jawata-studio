# jawata-studio v3.12.5 — the dashboard row stops saying RUNNING for a project that is gone

Delete a project's directory out from under a running workspace and the
resident notices at once: it reports that project unreadable, names the
problem, hands back a remedy, and warns that refactorings are refused there.

v3.12.2 carried that verdict to the **Reporting** page and to the **tray**,
which now goes amber. The **Managed Projects** row on the Dashboard — the
place you actually look — went on showing a green **RUNNING** badge.

It was not lying. That dot reports the *service*: the resident process for
that project is up, which was true. What was missing is the other fact, and
the row showed one without the other.

Both are now shown, side by side: the phase badge as before, and beside it
**cannot be read** when the resident says so. Never instead of the phase —
the service really is running *and* the workspace cannot be read, and a reader
needs both.

## Where the answer comes from, and why that matters

From the canary readings **already taken**, not from a fresh question. The
dashboard polls every 2.5 seconds, and asking each resident about its health
at that rate is exactly the load the canary exists to space out. This is a
cached read: no probe, and no canary round requested.

A workspace nobody has observed yet is not marked unreadable. "Not yet known"
and "known to be broken" are different, and only the second one shows.

## Also

The per-project resolution report now carries each project's path, so a
consumer can join it to its own project list exactly instead of guessing that
a key maps to a project.
