# jawata-studio v4.6.15

**The deployed rules tell a client without the jawata chat to collect its hires with `hire_wait`, the stop hook waits for a hire correctly in that client, and the plans repository is one setting passed to every engine.** This release needs jawata-mcp 4.6.11.

## What changes

- **`hire_wait` in every client's rules.** The rules the studio deploys to Claude Code, Cursor, Antigravity, Claude Desktop and IntelliJ tell a client that runs jawata without the chat to call `hire_wait` after `hire`, since only the chat receives a hire's report as a new turn.
- **The stop hook knows the difference.** Beside a running hire, a stop in a plain client (its own grant file) is blocked with the instruction to call `hire_wait`; in the chat it is still a wait for the report. The hook also asks the engine for the plans of every session, because it sends no session id and would otherwise see only plans nobody owns, counts the engine's running hires, says which autonomy it read and from where, and never blocks twice on the same unchanged state. The state a block was made on is forgotten when the grant ends, so after `/autocontinue-off` and `/autocontinue` the next stop is pushed again and is not taken for a repeat.
- **The plans repository is one setting.** The studio's general settings carry one entry naming it, and the studio passes it to every engine it starts as `-Djawata.plans.dir`; unset, nothing is passed.
- **The studio takes the person's login-shell search path once at its start,** so the engines, the brains they start and a hire's shell find `mvn`.
- **Seats.** The test manager owns the dogfood after a release and the main seat names it at that point; the main seat says a pm hire names the sprint plan file in `boardFile`, which the engine now requires; the architect seat lists the document tool so it can write its architecture file into the plans repository.

## Known limits

- The hook rules are covered by tests, including one through the stop gate itself. The studio was not shown in a real editor window with a real quiet hire for these changes; that is the first dogfood run on this release.
- The setting that names the plans repository has no settings screen, and no script of ours reads it yet.
- Windows and macOS are run by CI, not by hand.
