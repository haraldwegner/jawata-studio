# jawata-studio v3.7.4

Two dogfoods of 3.7.3, two protections restored.

- **The `.java` hand-edit gate is back.** The guard's binary replacement held
  the shell half of its job (java text search blocked, the declared fallback
  honored) and silently dropped the other half: hand-editing a `.java` file
  required a declared `jawata-author:` authoring window under the script, and
  under the binary it required nothing — proven by a real editor edit going
  through unblocked. The guard runs its full script generation again, the
  installer removes the stale guard binary, and — like the observer — which
  generation is live is a declared contract, not a side effect of what's on
  disk. The gate cuts back to the binary only when the binary carries both
  halves.

- **The Cursor escape hatch works.** Cursor's shell guard told the agent to
  re-run with `jawata-fallback: <why>` — and then blocked that re-run, because
  the escape was advertised but never implemented. The declaration now
  proceeds and is logged, matching the other client. Found by a Cursor-agent
  dogfood; the fix is pinned by a test that runs the real script with that
  dogfood's exact commands.

Everything else from 3.7.3 stands: five hook events run the new programs, the
observer keeps its outcome capture, memory recall fires on file edits, and the
silence log explains every quiet hook.
