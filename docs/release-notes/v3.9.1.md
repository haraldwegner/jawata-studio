# jawata-studio v3.9.1

One lying gate fixed, and the client roster reduced to the four that matter.

## The red line in your first v3.9.0 deploy was ours, not Grok's

Deploying to Grok reported *"missing a Bearer http_headers.Authorization"* — about a
config that is correct and that Grok reads. The file writer had learned Grok's header
spelling (`headers`, a sub-table); the post-write checker still demanded Codex's
(`http_headers`, inline). The deploy wrote a working config, then our own gate reported
it failed.

Both now read the same per-client table, and a test drives writer-then-checker for every
TOML client so the pair cannot drift apart again.

## The roster is now the four clients that matter, plus Grok

**Cursor, Claude Code, Codex, GitHub Copilot CLI** — the four agents worth providing —
plus Grok's tools. Removed as deploy targets:

- **Claude Desktop** — not a development client; its private skill-zip export channel is
  gone with it.
- **Antigravity** no longer receives any writes. Deploying to it now says why —
  *"not supported: this client has no mechanism to connect jawata"* — instead of a
  generic skip. Removing old jawata entries from an existing Antigravity config still
  works.

If your settings previously carried Claude Desktop entries, they are ignored and your
file loads unchanged.
