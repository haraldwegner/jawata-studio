# v3.14.2 — the loop stands down when the human is present

Two changes, both from one morning of live use.

## The autocontinue loop respects your presence (studio#33)

The autonomy grant exists to keep an agent working while you are away. Three
measured defects made it push the agent while you were *right there*, and each
is fixed with a control test that goes red if the fix is reverted:

- **Your question is answered, not worked past.** A turn opened by your own
  question is never bounced into new work — answering you and waiting is the
  work. Before, the agent would answer and then be pushed into whatever came
  next, forcing you to interrupt it.
- **Esc ends the grant, not just the turn.** An interrupt used to release only
  the interrupted turn; the grant survived and pushed again on the very next
  stop, so the same session had to be interrupted repeatedly. Now the Esc key
  ends autonomous continuation itself — one word ("autocontinue") re-grants it
  when you want the loop back.
- **A decision ask really ends the grant.** The mechanism existed but was
  blind: the ask detector matched a fixed phrase list against raw text, so
  "say **go**", "yours to confirm" and "blocked on you" all sailed past it —
  markdown and punctuation broke the match. Detection is now punctuation-proof
  and covers the imperative shapes measured live, and the same detector feeds
  the grant-ending path.

## The review seat works first and asks last

`/review` no longer opens with a wall of bands for you to triage. The seat
detects, repairs what it can resolve itself (file edits for file-backed
findings, `set_form` for store-only ones), verifies, and comes back with one
screen: the batch diff, what it parked because resolving it would mean
guessing, and the deletion lane — which still acts only on entries you name.
A situation is never guessed: what the seat cannot derive from the entry's own
text is parked for you, not invented.
