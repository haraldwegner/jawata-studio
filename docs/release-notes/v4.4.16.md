# jawata-studio v4.4.16

**Whether a workspace counts as running is now decided in one place on the screens, and a gate fails when a screen writes the rule out again. Nothing you see in the window changes.**

## What went wrong

- **The rule "a workspace is live when one of its projects is running or starting" was written out four times on the screens** (the project list's Start/Stop button, its Delete menus, and the workspace list's live count and Delete buttons). A new phase, or a fifth copy, could make them disagree: a workspace that was starting could be deletable in one place and not in another.

## What changes

- **One module, `src/lib/workspaceLive.ts`, holds the rule,** and the project list and the workspace list read it. The window behaves as before: a starting workspace is as undeletable as a running one.
- **A new gate, `build/live-rule-gate.sh`, fails when a screen names both phases on one line again,** in either order and with either quote. It proves itself first: it plants each spelling and checks it fails on each, and that a type declaration listing the phases passes. It runs with the other local gates.

## Known limits

- **The rule is still written in Rust as well,** in the backend's deletion refusal and three other places, so the two languages are held together by the gate's text search only. Planned: the backend sends a `live` field with each project's status and the screens read it.

Works with jawata-mcp 4.4.17 and 4.4.18.
