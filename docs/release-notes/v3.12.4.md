# jawata-studio v3.12.4 — the loop, and the valve that wasn't one

**Fixes an endless loop introduced in v3.12.3. Update before using v3.12.3
with Cursor.**

## What happened

v3.12.3 held a message that asks you for a decision until a reviewer had read
it, and gave up after three attempts so it could never wedge a session.

The give-up was written inside the branch that handles a *retry* — a second
invocation the client marks as a retry. Claude Code marks them. **Cursor does
not**: it re-invokes with the flag unset, so every invocation looked like the
first, that branch was never entered, the ceiling was unreachable, and the
rule blocked forever. Observed on a live machine with the attempt counter at
11 and still climbing.

A safety valve on one path is not a safety valve. The bound now sits on the
rule itself, so it holds however a client re-invokes, and passing the ceiling
releases the turn outright instead of falling through to the rules below —
which would have let a different rule bounce the same turn, the same loop
under another name.

Pinned by a test written from the incident: a client that never marks a retry
is still released.

## Also in this release

**The review rule is back to decision-class scope.** It ran unconditionally
for one afternoon — on every message, including "yes, done". An independent
architect audit ruled that form a category error: "the reader sees the text
once" is a rendering-control requirement, and a stop hook fires *after* text
has already reached the screen and can only add a message, never replace one.
Every enforcement action therefore increased what you had to read.

So it holds only a message that asks you for a word, exempts replies to your
own questions, and is a **backstop** for a review-first discipline rather than
the trigger of a correction: the reviewer runs first, the draft exists only
inside its prompt, and its readback is the only text you see.

**One rule instead of two.** The scoped rule and the unconditional one were
the same rule at different scopes; the contract now declares one.

## Known, and not fixed here

**#23 remains open** — the gate still cannot read the final message it judges.
Everything above routes around that; none of it repairs it.
