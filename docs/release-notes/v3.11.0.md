# jawata-studio v3.11.0

You can now see where jawata is failing for you, and it will tell you — through
the agent, never through a pop-up.

## The field view and the seat lane

A new view shows what jawata recorded on this machine: the recurring error
shapes, which channels have gone dead, and how often the agent reached for
jawata versus falling back to text search. That last number carries its own
caveat rather than pretending to be complete — the calls that did NOT reach
jawata are visible only where a hook sits in the session, which today means
Claude Code and Cursor.

Beside it, a lane where the seats become visible objects. It ships with one
tile, `/report`: the pile it would draw from, what has already been reported,
whether reminders are on and why, and the checkbox that turns them off. The
tile names the difference between that checkbox and the separate no-nudges
switch, because two controls that both look like "stop talking to me" must say
which one they are.

## It tells you, rather than interrupting you

When an error shape has recurred three times, the agent mentions once — in the
session, one line — that `/report` exists. Never again for that shape, never
after you report it, and not at all with the switch off.

Separately, at most weekly and only when there is something to say, the agent
notes that failures are accumulating. The first two are plain; from the third
it asks whether jawata should go silent about failures, and ignoring the
question changes nothing — the checkbox stays one click away. Using `/report`
resets the count.

**No pop-ups, anywhere.** A test asserts the absence of every notification,
toast and dialog path in the code that speaks: the reminders reach you through
the agent's own words, or through a passive banner if you open the app.

## A canary for the machine with no agent running

Studio now asks each resident, periodically, one real memory question and one
real compiler question. If either fails, the tray icon and the dashboard stop
being green. This covers the case nothing else could: when no agent is running,
nobody consumes a failed answer, so nobody would ever surface it.

## The observer finally runs as its binary

The observer role has run as a shell script since the binaries shipped, because
its binary arm was a deliberate stub — and a cutover decided by file existence
rather than by capability froze the outcome log once already. The binary now
carries both halves it was missing (the outcome capture and the audit trail for
declared fallbacks), and the deploy retires the script it replaces. A test
refuses the generation flip unless the declaration names both halves.
