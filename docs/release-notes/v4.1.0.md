# v4.1.0 — the judge is given the plan's three situations, and its verdict has a lifetime

**Three patch releases on one defect shape is the design alarm, and it went off.**
v4.0.0 shipped the stop judge; v4.0.1 and v4.0.2 each fixed a defect in it and
each left the next one. Harald: *"What the fuck you are introducing new bugs
every patch — No, I want a fresh architect/auditor look at this."* Two
fresh-context reviews ran, independently, and agreed on the root: the gate was
inferring who may set a verdict, where it came from, and how long it lasts,
from a transcript the judged agent writes — three inferences, one failing per
release. The fourth defect was live in v4.0.2 and neither I nor the suite had
found it: spawning the judge three times without working tripped the idle
valve and ended the turn with no verdict read; meanwhile the agent that *did*
the work was wedged forever on the stale instruction.

## The policy, in his words

*"It is always the plan which needs to be performed and checkpoints."* Three
situations, and every stop is one of them:

1. **Between checkpoints.** There is always work left. No release here, no
   release the plan does not name. The only question is the architect's: a
   showstopper, or a redesign the plan must change for → halt. Anything within
   the agent's own design limits → fix it.
2. **At a checkpoint** — the agent believes the stage is done and the audit
   has run. Findings → fix them. Sign-off → is this a release gate the plan
   reserves to him? Halt. Otherwise this *is* the autocontinue case: proceed.
3. **At a checkpoint, refusals not converging.** Past his round cap the judge
   takes the architect's position on the dispute: fixable → name the fix;
   not → halt.

The seat's stance is now that decision tree and nothing else. It reads the
plan and the transcript itself, counts the refusals itself, and puts its
verdict on its last line.

## The one fact the gate owns

*"We had the agent saying I can fix and he did not move on."* That is the C3
stop of 2026-09-03, and it decides what the gate must enforce beyond the seat's
answer: **did work happen since the verdict was given?**

- Told to fix, did nothing → held, same message, every time. Re-spawning the
  judge changes nothing: a fresh verdict is accepted only once the last one is
  spent. Idling changes nothing: the idle valve is off while an instruction is
  unspent.
- Told to fix, did the work → the verdict is spent, in either direction. Not
  the stale instruction re-served (the v4.0.2 wedge); not a stale reservation
  honoured either. The next stop is judged fresh, and the judge sees the work.

One flag. It closes the wedge, the re-roll, and the self-disarm with the same
mechanism, and it is what makes the C3 case come out right.

## Verified against the artifact

Seven cases against a release build, every one the shape of a defect found
this week: told-not-done holds; re-roll after a kinder judge holds; four idle
attempts on an unspent instruction all hold; work spends the instruction and
demands a fresh consult; a fresh reservation after work is honoured; the
stance-file quotation is still refused; a judge that cites a reservation before
resolving is read from its last line.

## Housekeeping from the review

- The review-ceiling rule is gone from the gate. It blocked with a message and
  no exit; the seat now reads the round count itself and rules on the dispute.
- The early `Reserved` return that made a match arm unreachable — the v4.0.1
  defect's exact shape, in the file that defect was about — is gone. One reader.
- `judge_ran` is derived from the bound call ids rather than stored beside them,
  so a client omitting ids cannot leave the two disagreeing into a wedge.
- The verdict parser takes the last matching line, matches the word whole
  (`RESERVED is not warranted` is not a reservation), and accepts bulleted and
  quoted forms.

## What this is not

Both reviews named the real fix: the gate calls the judge itself, with a prompt
and transcript path it composes, and holds a single-use ruling in its own state
outside the transcript. That is the redesign; this release makes the current
shape correct and gives it the policy it was missing. The agent still writes
the judge's prompt, and the transcript is still a file it can write. Stated so
nobody reads this release as having closed that.
