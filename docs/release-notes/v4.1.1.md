# v4.1.1 — the architect is told to look at the run, and to ask who owns the guard

Three rules the architect seat did not have, plus the one duty that makes the
third of them possible. No code changed; the seat text is compiled into the
binary (`include_str!`), so this release is what puts them in front of every
client's `/refactor`.

## Rule 12 — the second different breakage

Written as a proposal during Sprint 28d (S9a.3b) and held unapplied since,
because `seats/architect.md` is deployed product. Harald's word arrived
2026-09-04.

A recurring symptom means a fix missed — ordinary, and not the architect's
business. A symptom that is DIFFERENT after each fix means the patches are
moving one defect around, each exposing the next face of one structure. Two in
a row is the alarm, and the shape to refuse is a third fix justified by *"this
one is different"* — a sentence that is true every single time.

Its live cost, and why it is a seat rule rather than another counter: studio
v3.7.8 through v3.7.16 in one day, then v3.16.1 through v3.17.2 across two.
Thirteen releases, two design flaws, both reachable at fix number two. The
counting half already exists and stays where it is — the patch-streak gate on
the dev machine. What no script can do is say whether the faces share a
structure.

## Rule 13 — a guard over a fact the class owns is broken encapsulation

Harald, 2026-09-04:

> "if a guard has not to watch something which is not in your hands, this is a
> valid task. But if a guard watches something which is owned by your class,
> this is almost a broken encapsulation, and encapsulation is the core idea of
> object oriented dev."

"Guard" here is an automated check — a test, an assertion, a CI gate, a repair
routine — never a guard clause. So for every guard in a reviewed change the
seat now asks who owns the fact it reads. Not ours (a third-party compiler, a
vendored upstream copy, the user's code): legitimate, say so, move on. Ours: a
finding, and the report must name what the owning object should render, declare
or make impossible instead.

The test sorted all six guards in one sprint stage on its first outing. The
exception is stated in the rule so a reader does not think it failed:
**ownership is at the instant the check runs**, which keeps regression goldens,
independently-shipping wire formats and defence-in-depth legitimate.

## Rule 14 — a run of repairs on one place is invisible to every reviewer but the architect

2026-09-04, Sprint 28d C6: one check was rewritten four times across four
rounds, each version answering exactly the case the last round named and each
leaving the same hole one step to the side. Five rounds ran and none said *this
is the fourth*. Both instruments were working as designed — an audit inspects
the changes since the last gate, and a fresh-context reviewer is fresh on
purpose, which is the same property that stops it knowing this place was
already repaired.

So the history is owed to the seat by its invoker, and the trigger is
mechanical rather than a judgement: the repair history of the lines the change
touches, kept to this effort's commits. Handed that history, the seat reads it;
NOT handed it, the seat says so as a stated limit rather than inferring there
was none.

## The duty that supplies it — the /sprint skill

The rule above is useless if nobody gathers the history, and the party that can
is the editor inside the refuse-repair-re-audit loop. `/sprint`'s execution
discipline now carries that: before handing a repair back for re-audit, ask
whether this place was repaired before in this effort; when it was, give the
auditor each previous version and what it answered — facts, never the author's
reasoning, which is what the freshness exists to exclude — and dispatch the
architect over the RUN rather than writing repair number three.

## What this does not do, stated so it is not read as more

- **No rule can summon the architect.** A seat runs when invoked; these are
  read once it is already looking. The mechanical half is the local
  patch-streak gate, and that half only sees releases — a run of four fixes
  inside one session with no release between them is caught by neither.
- Nothing in the hook, the conductor or the runner changed. There is no test to
  go green for prose in a stance; the honest check is the next run of fixes.
