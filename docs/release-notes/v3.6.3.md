# JAWATA Studio v3.6.3

**The menu-bar icon comes back, and the installer is signed.**

## The menu-bar icon

It has been missing on macOS since v3.6.0, and two attempts to fix it made it
worse. This release removes the cause rather than adjusting it again.

v3.6.0 changed the macOS icon to a *template image* — a form where the system
uses only the shape and tints it — on the reasoning that a dark disc would be
invisible against a dark menu bar. **That reasoning was wrong, and the proof was
in this product's own predecessor.** JavaLens Manager drew the same solid dark
disc, handed it over with no template flag, contained no macOS-specific tray
code at all, and its icon was visible on the same machine. macOS shows an
ordinary icon in full colour; it is template mode that reduces it to a shape,
and that is what made it disappear.

v3.6.1 then changed the *shape* of that template, which was correcting the wrong
thing a second time.

So macOS now gets exactly what Linux and Windows get: the branded mark, in
colour, with no special handling. Ninety-nine lines of macOS-only icon code are
gone, and the test that guarded the template's shape has been replaced by one
that guards the opposite — the icon must stay opaque and coloured, because an
outline-only image is the failure.

**Still unverified.** Every previous attempt was shipped on reasoning and none
was ever seen on a menu bar. What is different this time is that the shape being
shipped is one that demonstrably worked on this machine before.

## The installer is signed

Until now the download was unsigned, so macOS refused to open it normally — it
had to be right-clicked and confirmed past a warning about an unidentified
developer.

Releases are now signed with a Developer ID certificate and sent to Apple to be
notarized, which is the step that removes the warning. Nothing about the
application changes; only whether your machine trusts the installer on sight.

This is the first release built that way, so the signing itself is unproven. If
Apple rejects it the build still produces an installer — an unsigned one, as
before — and the log says why.

To check rather than assume, on the downloaded file:

```
spctl -a -vvv -t install jawata-studio_3.6.3_aarch64.dmg
```

`accepted` with `source=Notarized Developer ID` is the result that matters.

Linux and Windows builds are untouched.
