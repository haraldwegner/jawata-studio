# jawata-studio v3.7.1

Patch. Fixes the stop-gate script Studio writes into a client's configuration
when you deploy hooks. v3.7.0 shipped it with two defects that misbehave in
practice:

- an agent's message was blocked even when the agent HAD run the required
  check, because one ordinary tool call in between re-armed the check;
- the loop detector fired on any session that merely READ certain files in the
  repository, telling the agent to abandon correct work.

Also: a dropped or unwritable silence-log entry is now reported by `--explain`
instead of being indistinguishable from a hook that never ran.

If you have not deployed hooks from v3.7.0, nothing was affected.
