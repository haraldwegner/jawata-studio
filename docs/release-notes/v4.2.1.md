# jawata-studio v4.2.1

Three fixes, and what links them is that the product was doing something correct for a case
nobody had told it about. Nothing here was broken loudly; each one was wrong quietly, which is
why two of the three needed a second pair of eyes to find.

## Switching a workspace off is a decision, not a fault

The tray light judged health over the residents it probed. A workspace you had deliberately
switched off was not probed, so "everything I asked answered" and "everything is running" were
the same green — and if you switched one off while another was genuinely broken, you were shown
the quieter of two true things.

The tray now has a third state for it. All configured workspaces healthy is the solid dark
green it always was; **healthy with something switched off by choice is a hollow ring in a
lighter green** — visibly not a fault, visibly not everything. Broken, degraded or unknown stays
amber and working stays grey.

**The state is also carried in words, on every state, in the tooltip.** That is not a nicety
beside the colour: green against amber is the pair that deuteranopia flattens, and unlike the two
greens it has no shape difference to fall back on. The tooltip names which workspaces are off,
which are still importing and how long they have been, and what is wrong with the ones that are
wrong.

**And it stopped costing you anything to configure your machine.** A late fix caught during
review: the new state fell into the short recheck cadence meant for faults, so a machine with a
workspace switched off asked every remaining resident two questions every fifteen seconds
instead of every five minutes — permanently, twenty times more often than intended, in exactly
the setup this release exists to render properly. Nothing failed and the light was right; only
the cost was wrong, which is why nothing could see it.

## The stop gate had been silent on this machine, and the reason was a deploy order

Deploying the hooks for one editor stamped the shared configuration with that editor's name,
while always writing it into the other editor's directory. The binaries registered there then
asked for a role that editor does not have, and answered silently to every stop.

Measured on a live session: **thirty-two stop events, and all thirty-two were "this role does not
exist on this client"** — while the record showed the session's own autonomy as granted. Every
rule that rides that gate was inert.

The editor is no longer passed as an argument. It is derived from the directory being written,
so there is no argument left to pair with the wrong one. The same defect had already bitten in
the other direction once and been fixed on that side alone; a guard would have had to be right
twice.

## Two tests could reach into each other's backup area

The backups root is a single process-wide value, and only some of the writers took the lock that
was supposed to protect it. A lock only some participants take is not a lock: two tests running
at once could move each other's root, which is the substrate of an intermittent failure that had
been dismissed as a flake.

Each test now has its own root, so no other test can reach it — a deterministic reproduction
replaced a one-in-five failure.

## Also in this release

- The health check's first wait can now be cut short. It exists so a just-started resident is
  not called dead while it is still booting; a resident coming up is exactly the news that makes
  waiting pointless, and previously nothing could interrupt it.
- The tooltip no longer renders an empty list where it means to name what is still starting.
