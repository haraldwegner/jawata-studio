# jawata-studio v3.14.0

**Autocontinue works.** For the first time.

## The signal that was never wired

`stop::judge` has carried Rule B since Sprint 26 — *"do not stop when autonomy is
granted and nothing is armed"* — and the single production call site passed
`Autonomy::Unknown`. The rule is gated on `Granted`, so the comparison was false
on every stop the product has ever made. `stop.rs` recorded the consequence in
its own comment: the rule *"never fired in 267 recorded stops, and the cause was
detection"*.

Twenty-odd tests construct `Autonomy::Granted` and every one of them passes.
That is exactly why nothing ever went red: the rule, its message and its bound
were all covered, and the missing piece was an input.

Typing **`autocontinue`** in a prompt now grants it. That word reaches
`Role::UserPrompt`, which already parsed the prompt and already knew the session
— both ends existed the whole time and were never joined. Nothing else grants
it: no inference from "continue", "keep going" or "carry on", because a grant the
human did not knowingly give is worse than none.

When the agent then tries to end a turn with no background work running, the gate
refuses and hands back: *"autonomy is granted and this turn armed no background
work, so ending here sleeps until the human returns. Start the next piece of
work, or state plainly that you are blocked on the human."*

## Two ways it ends, neither of which you have to remember

- **Your answer is needed.** The grant clears itself the moment the agent's own
  message asks for a decision, a release or a ruling — the same condition the
  gate already computed for the review rule. A switch you have to remember to
  throw is off exactly when you are least able to throw it, which is while you
  are asleep. A reply to your own question does not count, or every answer you
  asked for would switch your autonomy off.
- **Escape.** An interrupt beats the grant, always — both stopping the reply and
  stopping a tool mid-flight. The grant covers your ABSENCE; an interrupt is the
  loudest possible evidence that you are present. Read from the transcript, which
  the harness writes, so the agent can neither forge one to escape the gate nor
  omit one to keep a session running.

## The bound, and why it is not a limit on the feature

Wire a rule like this without a ceiling and a session with nothing left to do is
trapped. Two obvious ceilings are wrong:

- On the retry flag — that is what v3.12.3 did, and Cursor re-invokes with it
  unset, so the ceiling was unreachable and the rule blocked forever.
- On the number of blocks — that releases a WORKING session as fast as a stuck
  one: pushed, worked, pushed, worked, and after N pushes the valve switches off
  the feature it guards.

So the ceiling counts consecutive turns that produced **no tool calls**. Work
resets it; two empty turns release the session; and a turn of yours resets it
too, because a wedge is empty turns with no human input between them. A bound
that cannot be persisted is treated as SPENT rather than zero — a discarded
`Result` fails exactly as quietly as a success.

**Known limit, stated rather than left to be found:** "did work" is not "made
progress". An agent that spins — one tool call a turn, going nowhere — resets the
counter indefinitely. Escape is the backstop.

## Also

- **`/review` seat.** Shows what the store carries that nobody uses and what it
  is asked for and does not have. Two lists, never merged: entries shown often
  and chosen never, and questions asked repeatedly that nothing answered. It
  deletes only what you name, through a verb that archives first.
- **`/memorize` no longer says STORE FIRST**, because that now loses the story.
  The store is rebuilt from a file substrate, so a direct record has no file
  behind it and the next reseed removes it. It asks the store where the substrate
  is, writes a file, stamps it only if the cold reader passed it, and echoes the
  full text of what it stored — this command was pressed for months in the belief
  that it extracted a useful story while it stored one compressed line, and the
  only reason that went unnoticed is that its report never showed what went in.
- **The architect seat consults the pattern catalogue** and judges a pattern the
  way its own literature asks: does its situation describe the design in front of
  you, and are its consequences ones you are willing to pay?
