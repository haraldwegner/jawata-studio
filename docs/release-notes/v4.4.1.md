# jawata-studio v4.4.1

**The Seats tab scrolls, shows only what you decide with, and a seat's brain is read off your machine and tested before it is chosen.**

## What went wrong

- **The Seats tab did not scroll.** Its page lacked the app's scroll container, so on a normal screen only the first few of the fourteen seats could be reached.
- **It showed things nobody decides with**: each seat's tool list, its gate classes, and a cron schedule that nothing runs. It named seats by their internal name (`architect`) instead of the command you type (`/refactor`), and gave one line of explanation beside an on/off switch.
- **The Brain row showed model names written by hand** into the seat files (`claude-sonnet-5`, `claude-haiku-4-5`). Nothing on the machine had confirmed them, and a seat you type in a chat never used them.
- **The UX seat judged a view against the spec, not from the person using it.** It passed a page that could not scroll, and kept rows nobody acts on because a spec sentence named them.

## What changes

- **The Seats tab uses the app's page layout**: it scrolls, in two columns like Memory and Reporting.
- **Each seat shows what you decide with**: its name with how it is called — `architect (/refactor)`, `pm (hired by a seat)`, `spec-auditor (inside /sprint)` — an explanation of what it does for you and what it never does, when it is used, its brain, and its on/off switch. Every control and term has a mouseover.
- **The brain is a dropdown read off this machine**: the agent programs a hire can start (Claude Code, Codex, Cursor, Copilot) that are installed here, whether each is logged in, and the models each names for itself. Nothing in the list is typed by hand.
- **Choosing an entry runs a one-word test through that brain first**, and the choice is saved only if it answers. The test shows the time, the model that actually answered, and the cost where the brain reports one (Claude Code: under a cent, measured). If the brain does not answer, you see its own reason and the command to log in with in a terminal, and the previous choice stays.
- **A saved choice is what a hire uses**: it is written into the seat file the engine's hire reads, the seat keeps receiving updates, and Reset removes it. Model names are gone from every shipped seat; a seat with no choice runs on its brain's own default model.
- **The UX seat (`/ux`) looks at a screen as the person using it**: it renders the view to check that everything can be reached, keeps only what you decide or configure with, asks for explanations enough to act on, the name you type, and mouseovers — and proposes the lean view itself.

## Known limits

- **Grok is not offered**, even where it is installed: the engine's hire cannot start it yet.
- **Claude Code has no command that lists an account's models**, so its entries are the names its own help gives (`sonnet`, `opus`, `fable`, …). The cheaper Haiku is not among them: the seats measured as fine on the small model now run on the brain's default (Opus on Claude Code) when hired, unless you choose `sonnet`.
- **Each test run spends a little** of the chosen brain's account.
- **Logging a brain in is done once, in a terminal.** The view tells you the command; it never handles a credential.
- Windows and macOS remain as unproven as in 4.4.0.
- The new seat files reach a machine at its next deploy. A seat you edited by hand keeps your version.

Ships with jawata-mcp 4.4.1, in which a hired seat receives its own rules and a hired Claude talks only to the jawata that hired it.
