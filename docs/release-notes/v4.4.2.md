# jawata-studio v4.4.2

**A resident that answers nothing says so in words, the fleet start waits for each import, and the Seats view writes what the engine's hire reads.**

## What went wrong

- **A resident could be alive and deaf, and the tray said only "store not answering".** When both canary questions get no HTTP answer the whole resident is silent, and the cure is a restart, not a look at the store. An engine that exits because its listener died (status 70) read as a bare "exited unexpectedly with status 70".
- **Restarting the services from the tray froze a machine for about five minutes.** Three residents re-imported their workspaces at once under a start that only spaced the launches.
- **The hook split a Windows path wrongly and ran a script it was told not to.** A backslash was read as an escape, so `C:\Users\x` became `C:Usersx`, and `-n` or `-o noexec` still executed the command.
- **Turning a seat off did nothing the engine could see,** and turning one off or undeploying removed a command the app had not written.
- **The help said "45 tools"** while the engine publishes 44, and told the reader to revert with a tool that no longer exists.

## What changes

- **`<workspace>: not accepting connections`** appears in the tray and its tooltip when both canary probes got no HTTP answer; a store that is silent while the compiler answers keeps "store not answering". A status-70 exit says its HTTP listener stopped answering and that the exit is by design.
- **A fleet start waits for each workspace's import to finish** before the next one starts, held to the engine's own health answer, and no fleet action runs on the UI thread.
- **The hook** keeps a Windows path's separators, and a shell told not to execute runs no script.
- **Seats:** switching a seat off writes `enabled: false` into its seat file and the scheduler skips it; a change in the Seats view deploys the seat commands only, not every client's MCP configuration; a seat's description comes from its own purpose line; a seat file may name the script brain's executable; choosing a brain held only by an instruction writes the `accepts_uncontained_writes: true` opt-in the engine's hire checks. The list of brains the engine holds only by an instruction, and the list of hirable brains, are pinned to the engine's own answer by a test.
- **The test-manager seat** asks for the reach of a change through `inspect(kind=impacted_tests)`, declares the mutation run as a gate step, and has a cost ceiling of 4.0 (the measured need was 2.2 to 3.1).
- **The tray** sends an unchanged verdict's icon again once a minute, and the verdict's words are the menu's first row.
- **The help** states no count of the engine's tools and names `refactoring(action=undo)`. A test fails on any digit before the word "tools".

## Known limits

- **Windows is not exercised.** The hook tests that build Windows paths are ignored on Windows until a runner proves them.
- **Nothing restarts a resident that exited Failed** without a user action, including after status 70; the red tray and the new words are the signal. A bounded automatic restart was left out because each restart is a heavy JVM start.
- **"Not accepting connections" is also shown for a slow resident** whose probes time out.
- **The fleet start's behaviour under a CPU ceiling has not been measured on a live restart,** only the rule it follows.

Works with jawata-mcp 4.4.6.
