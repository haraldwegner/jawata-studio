# jawata-studio v4.3.4

**Accepting a memory entry writes its story file again, and memory answers are fast.**

## What went wrong

- **Accepted entries got no story file.** The engine only wrote a story file when it was started
  with a story folder set, and studio never set one. So accepting an entry — which `/memorize`
  says writes the file — wrote nothing, and nothing said so.
- **Memory answers took one and a half seconds each.** Every question read the whole store from
  the database again. With ten thousand entries the Reporting screen marked the store "too slow
  to use".

## What changes

- **Settings → Story export folder:** left empty, an accepted entry's story file goes into the
  store's own story folder, the one its stories are loaded from. Type `off` to write no files.
- **Ships with jawata-mcp 4.3.3.** The engine keeps the store's word index and meaning vectors
  in memory and reads the database again only when something in it changed, so a question no
  longer reads the whole store. An accepted entry's story file is tied to its entry, so the
  reload studio does whenever an engine starts does not add that entry a second time.
