# jawata-studio v3.9.0

jawata now deploys to four more agents, and stops pretending to deploy to one it
never reached.

## Four new agents

**Codex**, **GitHub Copilot CLI**, **VS Code** and **Grok** join Cursor, Claude
Code and Claude Desktop. Every configuration path and file format here was
obtained by making each tool write its own config and reading the result back —
not from documentation, and not from memory. Two of those measurements overturned
what a careful guess would have produced:

**VS Code keeps its servers under `servers`, not `mcpServers`** — the key every
other client uses. Writing to the wrong one produces a perfectly valid file under
a key VS Code never reads: a deploy that reports success and changes nothing.

**Codex spells "off" as `enabled = false`, not `disabled = true`** — the inverse
of every JSON client. A server meant to be switched off would have stayed on
while the deploy reported success.

Codex and Grok are TOML rather than JSON, and differ from each other too: Codex
keeps the bearer token in an inline `http_headers` table, Grok in a `headers`
sub-table. Comments and settings you already have in those files survive a
deploy — Grok's own `mcp add` deletes them; jawata's writer does not. A file that
cannot be parsed is now refused rather than overwritten, on both formats.

Grok's own `grok mcp doctor` confirms the result end to end: handshake complete,
45 tools discovered, against a config jawata wrote.

## IntelliJ is no longer a deploy target, because it never needed to be

IntelliJ hosts Claude Code, Cursor, Codex and Copilot as agents that read their
own configuration files. Deploying those four already reaches it. The dedicated
IntelliJ target was writing into `~/.config/JetBrains/IntelliJIdea/` — an
unversioned folder jawata created and then wrote into alone, while the real
product folders are versioned. **That deploy reported success for its entire
existence and was read by nothing.**

If you want jawata inside JetBrains' own assistants rather than a hosted agent,
the file they read is `~/.ai/mcp/mcp.json` — the path IntelliJ prints in its own
"New MCP Server" dialog.

## The client list has one home now

Adding an agent used to mean editing more than a dozen places, and missing one
was silent. The worst case had already shipped: Claude Desktop was undeployable
for the life of the feature because the deploy screen sent one spelling of its
name and the backend expected another, and the run then reported "Skipped: not
selected in this deploy run" for a box you had ticked.

There is now a single client roster, and every other description of a client is
checked against it — the settings file, the deploy list, the deploy screen's own
source, and this product's help file. Reintroducing that exact mismatch now fails
the build.

Relatedly, when a deploy is asked for a client id it does not know, it no longer
says only "unknown id". If what you sent is the settings key for a real client,
it tells you so and names the id to use.

## Two things that told you something untrue

**Diagnostics showed the wrong data root.** It displayed the operating system
default while "Clean workspaces" empties the root you actually configured. If you
had ever changed it, that line named a folder nothing would touch. It now shows
what cleanup targets, and marks it as overridden when it differs.

**The deploy summary never went away, and could mislead after a failure.** It had
no dismiss and survived the session; worse, a failed deploy left the previous
run's *success* in place, so clearing the error revealed that success again as
though it described what had just happened. Starting a deploy now retires the old
summary, and the summary can be dismissed.

## Also

An automatic refresh could not see a Codex or VS Code deployment, so their entries
would have gone stale silently whenever you added or renamed a workspace. The
gateway's consolidated entry could never be removed: an undeploy reported "nothing
to remove" and left it pointing at a service no longer running.

The help file described a four-client roster from two sprints ago and quoted a
40-tool budget against a 45-tool surface. It now documents where every supported
client keeps its configuration, including the folder that differs between Linux,
macOS and Windows.
