# jawata-studio v3.12.2 — the dashboard tells you what the resident told it

## An unreadable workspace is no longer green

Delete a project's directory out from under a running workspace and the
resident notices immediately: it reports that project `healthy: false`, names
the problem — *"registered, but its directory NO LONGER EXISTS on disk"* — hands
back a remedy you can run, and warns that refactorings are refused there,
because a rename cannot see references in a project it cannot read.

The studio threw all of that away and drew a green dot.

The cause was one predicate. The report dropped every project whose unresolved-
dependency count was zero **before** it asked whether the project could be read
at all — and a project whose directory is gone has zero unresolved dependencies,
because there is nothing left to resolve. The single state that must never be
hidden was the single state guaranteed to be filtered out.

Now the report keeps a project that is unresolved **or** unreadable, and carries
the resident's own words with it: the problem and the remedy per project, the
warning per workspace. The canary asks the workspace question too — neither the
store probe nor the compiler probe can see a missing directory.

The engine's guard was armed the whole time; a refactoring there would have been
refused. What was broken was the surface you use to find out.

Closes **#24**. It is the exact inverse of **#16**, closed the same afternoon:
that one painted a healthy launch amber, this one painted an unreadable
workspace green. One root — the colour came from "the process is up" rather than
from the resident's verdict.

## Every stop now shows a message-review pass

The rule requiring an outgoing message to be reviewed before it reaches you was
gated on a condition the running product never sets. In 267 recorded stops it
had never fired once; 245 of them recorded "autonomy unknown" and enforced
nothing.

That condition was also what made the rule unimplementable. Every conditional
form — too long, asks for a decision, undefined terms — has to read the final
message, and the final message is the one part of a turn that is not yet written
down when the stop fires (**#23**). An unconditional rule needs a single fact,
whether the reviewer ran, and that is recorded before the stop. It is the only
rule here that is both always relevant and always answerable.

Two assumptions were deleted rather than patched: that ordinary conversation
should be exempt, and that replies should be. The misleading status sentence
that prompted this rode a reply.

## Known, and stated rather than hidden

**#23 is still open.** The unconditional rule routes around the stale-turn
