# jawata-studio v4.3.0

The client half of the store sprint. The engine gained four lanes and a code lane; this is what
reaches an agent, and when. The thread through all of it: **a moment fires as a side effect of
ordinary work, or it does not fire at all.** A capability that waits for someone to remember to
run it is not shipped, and this product has shipped one that way before.

## A file edit alone triggers nothing

The recall hook used to take the file's own path, break it into words, and ask the store what it
knew about "importer" — on every edit of every file. That is not any lane's moment.

It is silent now, and it says WHICH RULE stopped it rather than reporting the store as having
nothing. Those are different facts and they used to print the same.

Each lane keeps its own moment instead: experience fires on a prompt's symptom cues and on a tool
call carrying a `Type#member` cue; domain fires when a call reads a type the domain lane anchors;
the code lane's map arrives at the prompt and a package's areas on the first read into it.

## The duplicate gate

A `Write` or `Edit` that adds a method to a `.java` file has its draft read, its methods asked of
the code lane by meaning, and the nearest recorded job shown with its address — before the method
is written, which is the only moment the telling is free.

It SHOWS and does not DENY. That is a declared deviation from the plan and the reason is measured:
the ranking carries no score threshold, so rank one always comes back, and a gate denying on that
would deny every Java write. `Block` exists, must be asked for by name, and a word nobody
recognises never escalates to it.

**It says what it could NOT check.** When no project is loaded — which is the common case on a
hook, and always the case for a file being created — the gate cannot tell "this job exists
elsewhere" from "the method you are writing is already in this very file". It now says so in the
same breath as the nominee, rather than printing a confident sentence over an unchecked one.

**An agent may order a second implementation, and the reason is required.** Put
`jawata-duplicate: <why>` in the call and the write proceeds with the reason logged for the
architect's watch. A bare marker is refused: a one-word bypass turns a rule into a ritual, and the
cost lands on whoever next meets the two implementations and has to work out from scratch whether
the duplication was a decision or an accident.

## The architect seat learns to look for the duplicate it cannot see

D-SIX — refuse a second implementation of a job the system already does — gained a DETECT step
with two calls: the compiler-accurate `re_derived_job` detector, and the store's own answer for
the package under review. A report that orders a duplicate on purpose must carry its reason, and
the seat's own gate refuses one that does not.

**Half of that detection had never run.** The seat instructed a store call that named no search
term, so its entire answer was the store's "no cue" refusal, every time. It reads like a detection
step and was one round trip to a refusal. It is fixed, it now asks for the package's whole
population rather than the first five rows of it, and a new guard fails the build if any seat
instructs a search with nothing to search on.

## The cataloguer seat, and `/catalogue`

A seat that describes what each member and each package is FOR, resumably — it takes a bundle,
records a job per member and an area per package, and closes each unit so a later run picks up
where it stopped rather than starting again.

## Memory view

Backups and restore by name, the four lanes shown separately, rule versions and retirement, and
which members and packages have been described against those that have not. The export folder is configurable
in runtime settings.
