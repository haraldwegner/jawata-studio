# jawata-studio v4.4.12

**Agent deploy is its own panel, Reporting scrolls once, and the studio says "workspace" where it said "resident".**

## What went wrong

- **Agent deploy sat inside Managed Projects,** although it writes your agents' config files and Managed Projects starts and stops workspaces.
- **Reporting had two scrollbars:** the failure-shape list scrolled inside the panel that already scrolls, so the wheel moved one or the other.
- **The tray said "3 of 3 residents healthy"** and several views, tooltips and messages said "resident" — an engineers' word for the process that serves a workspace.

## What changes

- **Dashboard:** Agent deploy is a second panel under Managed Projects, always visible. It holds Deploy to agents, Remove from agents, the agent picker and the result line; Managed Projects takes the free height and scrolls inside itself.
- **Reporting:** the list of failure shapes has no scrollbar of its own; the one panel scrolls.
- **Wording:** the tray reads "Workspaces — 3 of 3 healthy"; Reporting reads "workspaces answering" and "Workspaces not answering"; the Memory, Dashboard and Settings texts and tooltips say "workspace".
- **Help:** step 5 names the Agent deploy panel.

## Known limits

- **"Is a workspace running" is still worked out in several places** (ledger S19-10); the answers agree today and nothing on screen changes. It moves to the backend in a later release.
- **Reporting still shows three totals** (recorded, filed, still to report); a fourth, "seen 3 or more times", would need the backend to publish it.
- **Help has no screenshots yet;** they are made once the other views are done.
- **The Dashboard's project rows, the About dialog's version lines and the tray menu were not rendered** (a static render cannot show the native tray menu or whether a panel scrolls).

Works with jawata-mcp 4.4.15.
