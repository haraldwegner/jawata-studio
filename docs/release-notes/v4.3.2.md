# jawata-studio v4.3.2

**The architect review stops reporting look-alike methods as duplicated work.**

## What went wrong

The architect seat (`/refactor`) checks whether new code re-implements something the codebase
already does. To find candidates it asked a detector that groups methods by the shape of their
signatures and the types they use. That is not the same as doing the same job. On jawata's own
code the detector reported 581 groups; its first group put nineteen unrelated methods together —
plugin directories, workspace paths, degradation notices — because they return the same kind of
list.

## What changes

The seat now asks the code catalogue: the description of what each method is for, written by
`/catalogue`.

- Where a package has not been catalogued yet, the review says so in one line —
  `NOT CATALOGUED: <package> — D-SIX not checked` — and reports no duplicate finding there,
  rather than reporting look-alike groups as findings.
- New code in the change under review is checked with the store's duplicate check, which shows
  the catalogued jobs nearest in meaning, each with its location.

Nothing else in studio changes. Works with jawata-mcp 4.3.0 and later.
