# jawata-studio v4.4.13

**Help carries screenshots of every view, the Memory wait counts its seconds in dots, and the install line points at jawata.org.**

## What changes

- **Help:** twelve screenshots of the installed 4.4.12 window sit under the step or section they show: adding projects, the found projects, a workspace card, the running workspaces with the Agent deploy panel, the agent picker, Memory, Reporting, Seats, Settings (Engine, Agents, This machine) and the tray menu. The old six screenshots are gone.
- **Memory:** while the first read of the store has not answered, "Reading the store…" grows by a dot a second (and starts over after ten), so a wait of more than five seconds shows that the window is working.
- **Install:** the README and Help give `curl -fsSL https://jawata.org/install.sh | bash`.
- **Test harness:** `build/ux-render/render.sh` no longer leaves its test server running (a dozen were left over two days), and it renders the slow-store wait.

## Known limits

- **Scrolling still stutters a little on every tab, Reporting most.** The studio forces WebKitGTK, the browser engine that draws its window on Linux, to paint on the processor. Whether that, or the content, is the cause is not settled; a test with graphics-card painting allowed again is open.
- **The first read of the store takes more than five seconds** on a store of about 12,000 entries; why is not examined, and the window still starts the read on every visit to Memory.
- **The tray menu and whether each panel scrolls cannot be rendered** by the harness.

Works with jawata-mcp 4.4.15.
