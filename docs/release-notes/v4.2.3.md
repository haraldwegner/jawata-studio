# jawata-studio v4.2.3

The tray tells you what is happening while it happens. Everything here came from using
v4.2.2 rather than from a test.

## The colour changes when you change something, not when the next check runs

Stopping a workspace from the tray menu left the icon showing its old verdict for **up to
five minutes**.

The menu called the manager directly, while only the dashboard asked for a fresh check —
one operation, two callers, and one of them remembering the follow-up. The wait it left you
in was the worst available: the verdict standing before a stop is *healthy*, which is
deliberately checked least often, precisely because a healthy machine does not need asking.
Stopping is exactly what makes that answer wrong.

Underneath was something worse. The five-second check reports nothing when no workspace is
running, so with everything stopped it had nothing to say at all — the tray could only reach
"nothing running" via the five-minute round. An indicator that cannot express a state is
worse than a slow one, because nothing about it looks wrong.

So the tray now answers **from what you asked for**, with no check needed: it already knows
what is meant to be running and what everything last reported, so it repaints at once and
the check that follows merely confirms. The announcement is made at the one point every
start and stop passes through, so no future caller can forget it.

## The mark now has two parts, and each says a different thing

**The ring** says how the running workspaces are doing. **What fills it** says what is
happening with the rest.

| | |
|---|---|
| nothing running | solid blue |
| starting, none ready yet | solid grey |
| some ready, **more coming** | green ring on **grey** |
| some ready, **rest switched off** | green ring on **blue** |
| all ready | solid dark green |
| something wrong | solid amber |

The two partial states were one state, which meant a cold start and a deliberate choice
looked identical — and they call for opposite responses: wait, or this is how it stays.

The solid marks are not exceptions to the scheme; they are what it looks like when both
parts agree. Blue means one thing throughout — *present, nothing being asked of it* — for
the whole machine when nothing runs, and for the part you switched off when something does.

**The outline is gone**, and not for looks: an outline's centre is whatever your menu bar
happens to be, which made it the one mark whose appearance belonged to your desktop theme
rather than to us — and it was the mark meaning "this is settled", so it is the one on
screen longest.

Amber stays solid whatever else is true. Something wrong is the only thing you must act on,
so it does not compete with news about what is idle.

## Known, and unchanged in this release

A workspace service that has just launched but has not yet opened its network port still
shows as a fault rather than as starting. It cannot answer, and a service that has died
cannot answer either — nothing yet tells the two apart.
