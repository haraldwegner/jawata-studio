# v3.16.0 — the stop gate holds a story that never reached the store

Writing the story file and reseeding it in are one job. The second half lived only
in instruction text, and on 2026-08-27 it was skipped: four stories were authored,
cold-read, stamped, committed and reported as remembered — while the store held none
of them. Every surface agreed everything was fine, because every surface asked the
store what it **had** rather than whether the files had **arrived**.

The first cure was a warning inside `stats`. Wrong channel, and this codebase already
knew it: a step that was never called cannot be caught by a report that is only seen
when you call something. An agent routes around friction without narrating it, so the
only channels that hold are the response, a hook, or a non-agent watcher.

## What the gate does

A turn that wrote a markdown file does not end while the store reports files under its
substrate root that no row cites. The block names them and carries the cure — the exact
`experience(kind=reseed, …)` call — plus the case that actually bites: a file returned
under `skipped` was refused, and most often owes a `reviewed:` stamp it has earned from
a cold reader.

Three properties, each one deliberate:

- **Asked only when the turn actually wrote markdown.** An ordinary turn ends with no
  round trip at all, and a stale draft someone left under the root does not hold every
  turn of every session forever.
- **It survives the retry.** The anti-loop valve lets every other rule through on the
  second pass. Here, doing nothing *is* the failure being caught, so a rule that could
  be walked past by waiting would not be a gate.
- **Bounded at two.** A reseed admits stamped stories only, so a draft that cannot earn
  its stamp reports drift no reseed will clear. Past the ceiling the turn is released.
  An unbounded hold is a wedge, and the ceiling sits on the rule rather than on one path
  through it — a valve behind a client-specific flag is no valve.

## Could-not-verify is not clean

A store that cannot answer holds nothing. Failing open is deliberate: a hook that wedged
a session because a resident was down would be worse than the defect it fixes. But "I did
not check" and "there was nothing to find" are different facts, and only the first is a
reason to look — so it writes `substrate-unverified` to the outcome log instead of passing
as a clean store.

Both causes are live today: the resident may be down, and **an engine older than
jawata-mcp v3.16.0 answers with no drift number at all**. Pair this release with that one
or the gate verifies nothing — visibly.
