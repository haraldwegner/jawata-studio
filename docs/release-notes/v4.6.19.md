# jawata-studio v4.6.19

**Antigravity's seat and utility commands arrive as skills it offers as slash commands, there is no per-seat choice of which agents get a seat command any more, and main's deployed rules say it never waits for a hire and leaves the test manager to the pm.** This release needs jawata-mcp 4.6.15 and goes with jawata-chat 0.2.15.

## What changes

- **Antigravity gets its commands.** A deploy now writes the seat and utility commands as skills into the `skills` folder beside Antigravity's MCP config, which `agy` 1.5.15 was measured to offer as slash commands (`/refactor`, `/review`, `/autocontinue`, `/autocontinue-off` in a throwaway home). The workflow files an earlier deploy wrote, which it offers none from, are retired; a file of the person's is left.
- **One rule for every agent.** The Clients row, the stored list of which agents get a seat command, the setting and its wire shape are removed; an old stored list is ignored. Every agent that can carry a seat command gets every seat that is on.
- **Main's deployed rule block** says main never calls `hire_wait` (a hire's report comes back as a turn) and that a test run is the pm's to hire.

## Known limits

- Not measured: the managed rule block's effect on Antigravity, and whether `agy` has guard hooks (proposed as a follow-up).
- Hires on Antigravity are not contained to the seat's rules (default mode wrote in 5 of 5 print runs, recorded earlier).
- Not run in the studio's own window; the Antigravity commands were measured in a throwaway home.
- Windows and macOS are run by CI, not by hand.
