# v4.0.1 — the retired reviewer was still deciding verdicts

**v4.0.0 said no gate consults the communicator. That was false as shipped, and
the dogfood found it.**

The reviewer RULE was retired correctly: nothing blocks a message for lacking a
communicator pass, and running it buys no length back. But one reader survived.
The anti-loop valve still called `owes_a_review()`:

```rust
if facts.already_bounced
    && !facts.turn.owes_a_review()   // ← still live in v4.0.0
    && !facts.owes_a_reseed()
    && !rule_b_would_push
```

So on a retry, a message that asked for something and had had no reviewer pass
was kept from being released — and spawning the retired subagent flipped it.
The subagent still decided a verdict, for a rule that no longer existed.

**Measured against the shipped binary**, one fixture, two runs differing only by
the communicator call:

| | verdict |
|---|---|
| retry, no reviewer | `TOO LONG` — blocked |
| retry, reviewer ran | **allowed** |

It fails safe — stricter without the subagent, and the escape needs a deliberate
spawn — so nothing was unsafe. It was still a rule the agent could get past by
consulting something the release said nothing consulted.

## The shape, again

This is the defect class this repository has shipped before and written down:
the rule removed from one implementation and left in a second reader that no
test covered. Every test of the retirement looked at the RULE. The valve is a
different site, and nothing pointed at it.

It was found by dogfooding the deployed artifact rather than by the suite, which
is the whole argument for that stage: the unit tests were green and correct
about the thing they examined.

## What changed

- The valve's `owes_a_review()` term is gone, and the predicate is deleted
  rather than left unused — an unread predicate beside a retired rule is how
  this survived a release.
- `pipeline.rs` no longer carries the bounce-charging arm that matched on
  `"UNJUDGED MESSAGE"`. No rule has emitted that string since v4.0.0, so the
  counter it maintained could only read zero, while looking like live state.
- A discriminator test, `the_retired_reviewer_cannot_change_a_verdict_on_any_path`,
  holds the general shape: on ANY path, spawning the retired reviewer must not
  change the verdict. Restore the valve term and it goes red — verified, not
  assumed: `Block(TOO LONG)` against `Allow`.

## Not in this patch

The Python stop-script generation in `manager_service.rs` still contains its own
`UNJUDGED ASK` block. It is unreachable — the deployed Stop hook is the binary
(`settings.json` invokes `jawata-hook-stop`, and no `stop-gate.sh` exists on
disk) — so removing it is cleanup rather than a fix, and it does not belong in a
patch release.
