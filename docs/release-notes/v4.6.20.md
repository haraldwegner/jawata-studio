# jawata-studio v4.6.20

**A deploy now puts jawata's guard on Antigravity too, a settings file the studio cannot read is shown in a window instead of the app closing, and a new workspace with no project survives a restart.** This release needs jawata-mcp 4.6.16 and goes with jawata-chat 0.2.16.

## What changes

- **Antigravity gets the guard.** A deploy adds one hook, `jawata-studio-guard`, to the `hooks.json` beside Antigravity's MCP config; your own hooks stay, and an undeploy removes only this one. Measured with `agy` 1.5.17 in a throwaway home: a text search and a hand edit on Java were refused, other calls passed. The guard is allowed to read Antigravity's own `~/.gemini` folder, as it is Claude Code's `~/.claude`.
- **A broken settings or projects file** opens a window naming the file and the reason. Before, the app exited with nothing. That start deploys, starts and writes nothing, so your file stays as it was.
- **A new workspace with no project** is still there after a restart.
- **"Cannot be read"** on a workspace now shows the engine's own reason, not a guessed one.
- **The Seats page** says once, not twice, that no engine is running.
- **Deployed rules** name who hires each helper correctly, and a refused planned check during a trial run is reported as not checked instead of being replaced by another search.

## Known limits

- The Antigravity guard was not deployed from the app and not run on Windows. Antigravity still gets no memory, prompt or stop hooks and no rule block, and hires on it are not contained to a seat's rules.
- Not run in the studio's own window; covered by the studio's tests.
- Windows and macOS are run by CI, not by hand.
