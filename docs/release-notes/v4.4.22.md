# jawata-studio v4.4.22

**An interrupted engine download now resumes where it stopped, and Settings says what the engine update is doing and when.**

4.4.20 and 4.4.21 were tagged and never published: their Windows builds stopped at tests of the hook's access-policy reader. 4.4.20 put Windows folder paths into JSON text without escaping their backslashes; 4.4.21 fixed that and then met the shared case file, which is written with POSIX paths. 4.4.22 carries the same change and marks that one test as ignored on Windows.

## What you see

- **A download that was cut off continues instead of starting over.** The next attempt asks the server for the rest of the file. If the server cannot resume, the download starts again from the beginning. If the downloaded archive will not unpack, studio deletes it, so a bad file cannot spoil the next attempt.
- **Settings shows two status lines, each with its time:** "downloading engine X" while it downloads, and "engine X installed, takes effect when the services restart" when it is in place. The same lines are in studio's log.
- **Every line of the release check in the studio log carries its time.**

## How it works

- The partly downloaded archive waits under one name per release in the engine tools folder, so a retry finds it. Installing an engine removes every waiting archive.
- A resumed download is appended to the waiting file; a server that ignores the request for the rest of the file gets the whole download again.

## Known limits

- The two status lines describe the engine update only; other downloads are unchanged.
- The hook's reader of the engine's access-policy file is in this release but nothing calls it yet. Its test against the shared cases does not run on Windows, which is the next round's work.
- Tried on Linux here. Not tried by hand on Windows or macOS.

Works with jawata-mcp 4.4.20.
