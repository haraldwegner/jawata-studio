# jawata-studio v3.7.12

Cursor's hooks are now configured, not just installed.

A hook binary finds its endpoint in `hook_config.json`, in the same folder as the
binary itself. The only code that wrote that file was the Claude Code deploy,
which wrote it into Claude Code's folder — so Cursor's binaries never had one.
They loaded "not configured" and went silent.

The effect was an installation that looks complete and does nothing. On the
Windows machine that found this, all four hook programs were present and
correctly named, the shell scripts were gone, the deploy reported success — and
the guard refused nothing, because it never got far enough to decide. The only
visible trace was a line in `hook_silence.log`.

The script generation could not have had this problem: each script carried the
address and token inside its own text. Moving to a single binary moved the
configuration into a file, and Cursor's copy of that file was never written.

Cursor's deploy now writes it, and a test fails if it stops.
