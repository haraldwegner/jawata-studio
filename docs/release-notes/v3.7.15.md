# jawata-studio v3.7.15

Prompt recall and the stop gate come back to life on Windows.

Your silence log had the answer written down: nine lines, every one of them a
prompt hook or a stop hook reporting a payload it could not read. Both were dead
on Windows — on every prompt, on every turn — while the install looked complete
in every listing.

The cause is a byte-order mark: an invisible marker Windows tooling puts at the
front of text. Rust's whitespace trimming does not remove it, so it slipped past
the emptiness check and then broke the JSON reader at the first character.
Reproduced exactly against the shipped program, and it now parses.

Every hook now reads its payload through one function, so tolerance is decided
once. Four of the previous six read sites discarded the failure without
recording anything at all — a payload problem there was invisible rather than
merely fatal.

## The error now says what it saw

"Payload is not JSON" names a category and nothing else: a byte-order mark, a
stray log line and a half-written file all produce it. Nine identical lines in a
live log could not be told apart, and diagnosing them meant reproducing the bug
by hand. Unreadable payloads now report their first bytes, and an empty payload
keeps its own separate diagnosis — different cause, different fix.

## Not fixed here

Whether the guard blocks a shell command on Windows is still unconfirmed. The
log shows the guard reading its payload and emitting a decision, so it is
running; the command it was asked about carried an explicit fallback
declaration, which it is supposed to allow. That test needs re-running without
the declaration.
