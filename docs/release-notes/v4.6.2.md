# jawata-studio v4.6.2

**The engine and the editor extensions now carry the Java work VS Code needed Red Hat's extension for; the studio tells its lead agents how a hire reports back.**

This release needs jawata-mcp 4.6.3 and the jawata chat and jawata Java extensions 0.2.2, which Deploy installs.

## What you see

- **The lead seats (main, project manager, chief engineer) are told how a hire works now:** it answers at once with its name, its result arrives later as a new turn, and a hire is asked to name the packages it works in, so an overlap with another running agent is refused before anything starts. The text is in the seat files; it is covered by the studio's seat tests, and no lead has been run on it here.
- **The engine in this release adds the editor's Java work** (refactorings at the cursor, the Testing view's requests, a debugger, a profile request) and the jawata Java extension 0.2.2 uses it; see the notes of jawata-mcp 4.6.3 and the extensions 0.2.2.

## Known limits

- Deploy still leaves Red Hat's Java extension in place. The studio has not yet been changed to remove it now that jawata Java covers refactoring, testing and debugging, and nothing here shows that the two together behave well.
- Copilot as the principal answers slowly (about a minute for a greeting here), because each turn carries the engine's tool definitions.
- Checked on Linux. Windows and macOS builds are produced but were not used by hand.
