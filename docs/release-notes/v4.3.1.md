# jawata-studio v4.3.1

**Fixes the empty memory store after upgrading to jawata 4.3.0.** Nothing you stored was lost —
it stayed on disk, and none of your workspaces could open it.

## What went wrong

jawata 4.3.0 changes the format the memory store is kept in — the first such change since
4.2.0. Since 4.2.0 the engine will not convert a store your workspaces share on its own
initiative: a workspace still running an older engine would refuse the store afterwards, so the
engine waits for a yes from whoever runs the workspaces. Studio runs them, and never gave that
yes. Each workspace declined and started on an empty temporary store instead, which is why the
Memory page showed `in-memory` with 0 entries.

## What changes

Studio now gives that yes when it starts a workspace while no other workspace is running — at
launch, and when you press **Reload all**. That workspace writes a backup of the store and then
converts it. Workspaces started after it find the store already converted.

Studio does not give the yes while another workspace is running, because that one may still be on
an older engine. A jawata you launched yourself, outside studio, is invisible to it.

## If your memory is empty now

Install this version and press **Reload all** once, from the tray menu or the dashboard.

One thing can linger for a single session. Studio starts workspaces 10 seconds apart. If the
conversion takes longer than that, the later workspaces pick up the converted store on their own
within 30 seconds, so memory works — but the engine keeps their learning layer offline until they
next restart. Pressing **Reload all** a second time clears it.
