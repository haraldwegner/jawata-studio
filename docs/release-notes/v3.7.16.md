# jawata-studio v3.7.16

Every Claude Code hook on Windows was failing to start. This fixes it.

Claude Code runs each hook command through bash. Bash treats a backslash as an
escape character, so the Windows path jawata wrote —

```
C:\Users\harald\.claude\jawata-studio\jawata-hook-primer.exe
```

— arrived as `C:Usersharald.claudejawata-studiojawata-hook-primer.exe`, and the
hook died with "command not found". All four roles, every session, on every
Windows machine: the session primer, prompt recall, the guard, and the stop gate.

Hook commands are now written with forward separators and quoted. Windows accepts
them, bash leaves them alone, and a profile path with a space still works. Linux
and macOS are untouched — a forward slash was never an escape there.

## Why this took six releases to find

The Claude plugin inside Cursor does not show hook errors. The command-line
client prints them plainly. Every diagnosis so far had been made from folder
listings and a silence log, because nothing on screen said a hook had failed to
launch — and a hook that never starts writes nothing to that log either.

That also settles an open question the wrong way round: the guard was never
letting shell commands through after deciding. It was never running at all.
