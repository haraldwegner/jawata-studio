# jawata-studio v4.6.17

**The Seats page stores each seat's brain and model in the engine, and a hire runs on exactly that choice: a seat file is no longer a source of brain or model, and a seat with nothing stored is not Claude, it is not set.** This release needs jawata-mcp 4.6.13 and goes with jawata-chat 0.2.13.

## What changes

- **One stored choice per seat.** Choosing a brain and model for a seat on the Seats page is written through the engine's `brains` tool, which checks it against what the engine can start and keeps it in one file (`seats-brains`, in the data folder the studio gives every engine with `-Djawata.seats.brains.file`). The page shows what the engine stores; a seat with nothing stored reads *not set*. The chat's drop-down and Agent Control show and write the same entry, and a change applies from the seat's next hire.
- **The seat files carry no brain.** `btw.md` and `rottenmeier.md` no longer name one. The two brain lines they used to carry are stored once as choices when the store file does not exist yet; a file that exists, even an empty one, is left as it is.
- **The principal's Cursor session asks for the newest model of a family** (`latest:grok`), not a fixed version. The engine reads the version numbers in the names the session offers and takes the highest; when the session offers no such model it stays on Cursor's own default and says so.
- **Seats.** The pm seat says only a seat's parent hires it, so the pm hires the two leads and not their workers.
- **The plans repository is declared per workspace.** The one machine-wide plans folder of 4.6.16 is replaced by a folder declared on each workspace and passed only to that workspace's engine as `-Djawata.plans.dir`; a blank one means none is declared. It applies at the workspace's next start and nothing is restarted. An older settings file that still carries `plansFolder` loads, and the key is ignored.
- **The client roster is the clients this machine drives.** IntelliJ (an IDE, like VS Code), Claude Desktop and Antigravity have no row in the deploy list.

## Known limits

- **Choices saved by an earlier studio in a seat file are not read.** Every seat except `btw` and `rottenmeier` reads *not set* until it is chosen once on the Seats page, and a hire of a seat that is not set is refused with a message naming the seat and the page.
- Covered by the studio's tests and, for the engine half, by a probe on a throwaway engine and with a real Claude (see the jawata-mcp 4.6.13 notes). **Not yet shown:** a change made on the Seats page seen in the chat's drop-down and Agent Control of a running studio, and the other way round.
- The per-workspace plans folder has a command and no settings screen yet.
- Windows and macOS are run by CI, not by hand.
