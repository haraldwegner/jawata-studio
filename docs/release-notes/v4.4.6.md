# jawata-studio v4.4.6

**The guard reaches an agent's attempt to switch autocontinue, a command typed inside a longer message says it was not applied, and the rottenmeier seat shows each rule's condition.**

## What went wrong

- **The guard never saw a Skill call.** The matcher the studio registers for the guard named Bash, Read, Edit and the other file tools but not `Skill`, so an agent's call of `/autocontinue` was launched and the refusal already written in the hook never ran. Found by the live check of 4.4.5: the call went through.
- **A tool called with no arguments was logged as "the event shape moved".** `hook_silence.log` named `health_check` as the client having changed, when the tool simply takes no arguments.
- **A command typed at the end of a longer message did nothing and said nothing.** `/autocontinue-off` as the last line of a message with other text is, by the two-command rule, not a switch. The mode line stayed `AUTOCONTINUE: ON` and stop verdicts kept recording a live grant for at least six minutes while he believed it was off.
- **The rottenmeier seat showed a proposed rule without its condition.** Its answer carried the rule's sentence, who it binds and a quoted turn, and no line saying when the rule applies, so the proposals could not be judged.

## What changes

- **The guard's matcher names `Skill`,** so a Skill call of `/autocontinue` or `/autocontinue-off` reaches the refusal.
- **A tool input that is an empty object is a silence for want of cues,** recorded as "the tool was called with no arguments". A non-empty input the hook cannot read still raises the moved-shape alarm.
- **A message that carries `/autocontinue` or `/autocontinue-off` on a line of its own inside longer text is told so.** The mode line gains "NOT APPLIED ... send the command alone", after the standing state, which is unchanged. The grant is not touched; the rule that a command counts only as the whole message stays. Machine text and a command named in a sentence are never flagged.
- **The rottenmeier seat states, for each proposal, a `WHEN:` line (something the agent can check: a call it is about to make, a task, a number) and a `DO:` line (the concrete action),** and leaves a rule unwritten if its condition cannot be written that way. Re-run on the same 185 corrections of his, it proposed 6 rules, each with both lines.

## Known limits

- **The notice informs the agent; it does not widen the switch.** Accepting a command on a line of its own inside a longer message would loosen the two-command rule, and he has not asked for that.
- **None of this has run on an installed copy yet.** The hook crate's 521 tests and the studio library tests pass; the live check waits for this release to be installed.
- **The list that shows a rule's condition and binding is the engine's** (jawata-mcp 4.4.11).

Works with jawata-mcp 4.4.11.
