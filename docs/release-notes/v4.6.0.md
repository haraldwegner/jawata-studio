# jawata-studio v4.6.0

**The studio takes on your editor's colours, the Workflow view is an org chart you can edit, and "Deploy to agents" sets VS Code up without fighting your Java extensions.**

This release needs jawata-mcp 4.6.0 and the jawata chat and jawata Java extensions 0.2.0, which Deploy installs.

## What you see

- **The Workflow view is an org chart.** It opens locked. Unlock it and drag a seat to move it; a move the engine refuses snaps back and says why. A right-click sets where a seat's failures go, and each seat's command and failure target are in its mouseover.
- **The studio follows VS Code's colours.** With a dark theme in VS Code the studio takes its colours within a second, and follows when you change theme. A light theme, or VS Code closed, leaves the studio in its own blue.
- **The principal's default brain** is set on the Seats view, and it is the brain the next conversation runs.
- **"Deploy to agents" leaves Red Hat's Java extension in place** and says why, until jawata has its own Testing view and debugger, and it no longer fails when Red Hat and the Test Runner are present.
- **Copilot is switched off in VS Code by Deploy**, and "Remove from agents" switches it back on.
- **The workspace list has no empty rows**, and a workspace you forgot stays gone.
- **New seats:** `developer`, `senior-developer` and `/btw`. The `worker` seat is gone; its work is done by those two.

## Known limits

- Checked on Linux. Windows and macOS builds are produced but were not used by hand.
- The cause of the empty `/` list and of the ten empty workspace rows seen on one machine was not found; both are guarded against, and the release's own check after a real deploy is what shows whether they are cured.
