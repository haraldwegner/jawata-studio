# jawata-studio v4.2.2

A dogfood patch on v4.2.1, and both fixes are the same mistake: the tray told you about
health it had never measured.

## Nothing running is now its own state, and it wears the company colour

Two situations produced a verdict that was simply not true.

**A fresh install showed dark green.** That icon is what the tray wears before its first
health check has run — and it was hard-coded to the healthy colour. Dark green means *every
workspace service was asked, and every one answered well*, so the tray was making that claim
before it had asked anything at all. It was the first thing a new user saw.

**Everything stopped showed the grass-green ring.** That mark means *running as configured,
and visibly less* — the state for deliberately switching a workspace off while the rest carry
on. But it is a reduction OF something, and with nothing running there is no healthy remainder
for it to be reduced from.

Both now show the **company blue**, which becomes a real state rather than decoration:
*nothing is running, so nothing has been asked.*

That is not the tray borrowing the logo to mean something. It is the opposite — the blue makes
**no** claim about health. It is what the product looks like when it is merely present, so a
change of brand changes how "nothing running" looks and leaves every verdict about a running
system exactly as it was. Each verdict keeps its own colour: dark green all healthy, grass-green
ring healthy with some switched off by choice, amber something is wrong, grey still working.

The tooltip says which of the two situations you are in — *nothing started yet* versus *nothing
running*, with the switched-off workspaces named — because they look identical in the tray and
are not the same thing to do something about.

## Known, and not fixed in this release

A workspace service that has just been launched but has not yet opened its network port still
shows amber. It cannot answer the health check at all, and the tray only shows "still importing"
when a service explicitly says that is what it is doing. A service that is genuinely dead also
fails to answer, and nothing today tells those two apart — so this needs the manager to pass on
what it knows about a service it just started, not a change of colour.

Found by dogfooding v4.2.1.
