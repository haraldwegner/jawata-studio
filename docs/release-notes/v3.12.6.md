# jawata-studio v3.12.6 — the message check stops mistaking emphasis for jargon

One of the stop-hook rules reads an agent's outgoing message and complains
about abbreviations it never explained. In the v3.12.5 session it complained
about six that did not exist.

What it had actually found were two labels: **NO LONGER EXISTS**, quoted out
of a resident's own reply, and **CANNOT BE READ**, the wording of the badge
this very release line added to the Dashboard. The rule split each into
words, saw short all-capitals tokens, and reported them as undefined
abbreviations. **BE** was the giveaway.

## The fix, and the shape of the old bug

A run of capitals is one label, not a list of abbreviations. A capitalised
word whose neighbour across a space or a hyphen is also capitalised is part of
a label, and is skipped.

The old behaviour was being absorbed by hand. A list of known terms had been
growing one ordinary English word at a time — OK, DONE, STOP, NOT, AND, THE,
ALL, NEW, YOUR, BOTH, RED, YES, NO — each added the day emphasis tripped the
rule. That list is for terms a reader of this project holds, not for the
dictionary, so those entries are gone and the studio's own badge words
(RUNNING, STOPPED, STARTING, FAILED) take their place.

A genuine acronym inside quotes is still reported. Quoting a log line does not
make it readable for someone who has never seen the term.

## Why there is no second mechanism

The first draft also blanked quoted and bold spans before scanning. With the
run rule in place that changed no verdict — the two halves covered each
other's cases, so neither could be shown to be doing any work, and removing
the redaction made the behaviour strictly better rather than worse. It is
gone. Both surviving halves are load-bearing: delete either one and the tests
go red.
