# v4.1.7 — the credential rule polices the reason, not the spelling

On Harald's instruction of 2026-09-08, the same day as v4.1.5 and v4.1.6. Built
from the v4.1.6 tag, so nothing else rides along.

## What was wrong

v4.1.6 folded a rule that refuses git introspection which would print a remote
address — because a remote address commonly embeds `user:TOKEN@host`, and
printing one puts it in the transcript permanently. That rule caught a real leak
on 2026-05-19.

Its config half listed the argument forms someone had seen: the two whole-config
dump flags, and the literal `remote.` **with the dot**. Git has more than one way
to ask the same question. `git config --get-regexp remote` prints
`remote.origin.url` and its token, and matched none of the three — no dump flag,
and no dot after `remote`.

**Measured on the deployed v4.1.6 binary rather than read off the source:** the
dotted spelling was refused and its regexp sibling was allowed. Same question,
same output, different spelling.

## What changed

The rule now asks whether the question can reach a remote address at all:

- a whole-config dump — it carries the remotes with it whatever else it carries;
- or any config read naming a **remote** or a **url**, however it asks. The bare
  word catches the regexp form that the dotted literal missed; `url` catches the
  urlmatch form and a regexp over URLs.

It deliberately does **not** become "any config read". Reading `user.name` cannot
reach a credential, and a refusal wide enough to catch ordinary work is one people
route around — after which it guards nothing at all. Both halves are asserted: six
spellings that must refuse, four that must not.

## Why this is a patch and not a note in the next minor

Until this ships, the rule is enforced on the author's machine by a local shell
script and nowhere else — which is the exact state v4.1.5 and v4.1.6 were released
to end. A rule that binds one machine is not a rule.

## The general lesson, recorded where a reader meets it

A list of spellings is only ever as complete as the day it was written. The fix
was to state the REASON — does this reach a credential — instead of enumerating
the ways of asking. The class of defect is named in the source above the rule, so
the next person to widen it widens the reason rather than appending a fourth
literal.

## Verification

Over the hook crate: **305 unit cases pass, 0 fail**, up from 303, with every one
of the 22 suites green. The two new cases are this rule's, one per half.

**Control:** reverting the rule to the dotted literal turns the refusal case red on
exactly the regexp spelling — *"must refuse: git config --get-regexp remote"* —
and leaves the must-allow case green, so the two halves discriminate separately.
