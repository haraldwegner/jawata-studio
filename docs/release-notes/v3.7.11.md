# jawata-studio v3.7.11

A deploy now cleans up after every earlier version, not just the ones it knows about.

v3.7.10 fixed the Windows hook naming and removed the shell scripts, but it left
behind what v3.7.9 had written: four role binaries named without `.exe`, which
no client can invoke and which no deploy would ever have touched. Retirement only
removed filenames the current code knows how to write — and those names came from
a bug, so nothing knew to look for them.

The rule is now the other way round. jawata owns the `jawata-` prefix inside a
client's hooks directory (and the legacy `goja-` one), so a deploy keeps exactly
the live generation and removes everything else carrying that prefix. That covers
misnamings nobody recorded, including future ones, instead of the specific
leftovers someone remembered.

Files outside the prefix are never touched — the configuration, the silence log,
and any hooks you added yourself keep their place. A test pins that, staged with
the exact residue found on a Windows 11 install.

Upgrading from any earlier version cleans the directory on the next deploy.
