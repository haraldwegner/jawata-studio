# jawata-studio v3.12.0 — the knowledge layer becomes visible, and the classpath honest

## Recall is observed, not assumed

The experience store answers on every prompt. Until now nothing watched what the
agent did with the answer — and a measured incident had a session receive the exact
prior solution to the problem it was debugging, on every turn, and reason past it
every time.

- **A session ledger** records what was injected and what was disposed
  (`recall-applied` / `recall-rejected: <reason>`), and a session that received
  knowledge and engaged with none of it is reported as `recall-skipped` at session
  end.
- **Counters on the Reporting page** — applied / rejected / blocked / skipped —
  carried with a coverage sentence naming where the mechanism cannot see: Cursor
  (no before-a-tool-call event, no agent-stop event) and Windows (the recall hook
  cannot read its payload there). A row of zeros never reads as "nobody ignored
  anything".
- **A turn that consumed a degraded tool result and does not say so is blocked**,
  with a reason naming what to add. Matched at the start of a line, so having *read
  about* degradation is not mistaken for having *been handed* it.

## The store says when it is unwell, not only when it is silent

The canary asked "did the store answer". The measured incident was not silence —
it was a read parked for 3459 seconds while the port kept accepting. The probe now
**measures**: the reading carries milliseconds, and the threshold is derived from
the hook's own effective budget, above which every recall on the machine is already
timing out one prompt at a time. A resident still importing is excluded from the
verdict; an unreadable store reports no latency at all rather than "3 ms, fastest
thing on the machine".

## Projects that resolved nothing now say so

The studio previously discarded the resident's health body and surfaced no
classpath data. A project that could not resolve its dependencies now appears on
the Reporting page with what it asked for and why it was not found — conditional,
so a clean workspace gains nothing. Everything-resolved is not nobody-answered, and
a runtime too old to emit the field under-reports rather than inventing a number.

## Pairs with jawata-mcp v3.12.0

That release makes a PDE/RCP workspace resolve as a whole (1229 → 0 errors on the
reference workspace). The unresolved rows this version renders are the honest
remainder of that work.
