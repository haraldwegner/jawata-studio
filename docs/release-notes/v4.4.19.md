# jawata-studio v4.4.19

**Studio now lists the Eclipse workspaces that run the jawata plug-in, whether Eclipse is running or not. The list is read-only.**

4.4.18 was tagged and never published: its Linux build stopped when the AppImage packing tool refused the repacked files for their owner-only permissions. 4.4.19 carries the same change and the permission fix in the release workflow.

## What you see

- **Each Eclipse workspace that has the jawata plug-in appears in the workspace list, marked "Eclipse",** as running or not running. The row has no switch, no start action and no click: studio only reports what the plug-in has written down.
- **The tray shows the same rows, greyed.** The list and the tray are built from one set of rows, so they cannot disagree.
- **A workspace studio has seen stays in the list.** When its Eclipse closes cleanly or dies, the row stays and reads "not running"; it does not disappear.

## How it works

- An Eclipse with the plug-in writes one small note per workspace into `jawata-studio/engines/` in the operating system's cache folder, and removes it at a clean stop. Studio reads these notes.
- Studio deletes no note, writes nothing into an Eclipse workspace and never opens the workspace folder a note names. A note whose process is gone is shown as "not running", because deleting it could remove the note of an Eclipse that is just restarting.
- The Rust reader and the Java one in the engine read the same set of fixture notes, byte for byte, so they cannot drift apart unnoticed. A test reads notes that real Eclipse instances wrote.

## Known limits

- Without the jawata plug-in in Eclipse, nothing appears: studio shows only workspaces whose Eclipse wrote a note.
- Studio does not start, stop or open an Eclipse workspace. That belongs to Eclipse.
- Not tried by hand on Windows or macOS; the reader and its tests ran on Linux here.

Works with jawata-mcp 4.4.18 and 4.4.20.
