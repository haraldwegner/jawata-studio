# v3.16.1 — the keyboard is the human; the harness is not

Interim release, one defect. v3.16.0's "stand down when the human is present" rule
could not tell the human from the harness — and the cost was measured, not
inferred: `stop-allowed` at 03:01:23, next human event 09:02. A session slept six
hours in the middle of a sprint it had the autonomy grant to finish.

## The defect

Task notifications arrive in the transcript as user-role lines, and an
agent-completion notice embeds the agent's whole report — text that virtually
always contains a question mark or a word like "what", "which", "check". The
"did the human ask?" detector keys on exactly those. So every window opened by an
agent's completion read as *the human is present and asked*, which stood down
both protections at once: the communicator review of self-initiated asks, and the
Rule B push that keeps a granted session working.

The cross-check that pins the mechanism: the same night, every Rule B push that
did fire sat in a window opened by a bash-completion notice — a one-line summary
with no question shape. Agent notices exempted, bash notices pushed. Exactly the
split the defect predicts.

A second amplifier sat in the pipeline: any ask-shaped final message ended the
autonomy grant outright, judged or not. The ask detector cannot tell a decision
from a checkpoint summary wearing a decision's clothes — so one manufactured
"DECISION:" ask switched autocontinue off for the rest of a night, and the
checkpoint loop the workflow runs on died at its first checkpoint.

## The fix

- **Only the keyboard is the human.** A harness line — task notice, system
  reminder, local-command echo — opens a new window but grants none of the
  human's exemptions. The ruling is pinned verbatim in the code, with its
  boundary: presence means keyboard **plus focus on the chat window**, and the
  gate satisfies that by construction because the transcript is the only input
  it can read.
- **Only a judged ask ends the grant.** The grant now ends on an ask that
  survived the communicator's review, or on Esc. An unjudged ask is bounced to
  the reviewer with the grant intact — a real decision ends autonomy correctly;
  a manufactured one dissolves and the work continues.
- **A typed dispatch still pushes.** "carry on" with no question does not stand
  Rule B down: that window is the grant at work, and the idle turn after it is
  exactly what the push exists for. The autocontinue wire tests assert this pair
  and are unchanged.

Two regression tests are named for the incident: the 03:01 shape now blocks for
review instead of sleeping, and an idle notification-opened turn is pushed.

## Verification

`cargo test -p jawata-hook`: 258 unit tests plus 18 integration suites, zero
failures — including the six autocontinue wire tests, untouched. An earlier
draft of the fix exempted every typed line from the push; those wire tests
refused it, and the draft was reverted rather than the tests.
