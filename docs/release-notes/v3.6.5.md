# JAWATA Studio v3.6.5

**The memory Studio installs was reaching nobody.**

## The recall hook injected nothing, for two weeks

Studio installs a small script that runs before every prompt you send. It asks the
experience store whether anything is known about the topic and puts the answer in
front of the agent.

It threw away any answer containing more than one item.

That rule came from an older contract, where the store returned a single fitting
fact or stayed silent. The store changed in v3.5.0: it now returns up to eleven
labelled candidates and lets the agent judge which fit — because a similarity
score cannot tell a real question from a nonsense one, so offering candidates and
saying so is the honest shape. From that release onward, every answer had more
than one item, so the script discarded all of them. Silently, on every prompt.

Nothing failed visibly. The script exited cleanly and emitted nothing, and there
was no signal anywhere that it had never fired. The only symptom was an agent that
kept re-deriving things already written down.

It now passes the candidates through, labelled as candidates rather than facts.

The check that was supposed to catch this could not: it fed the script a canned
single-line value and never touched the store, so it proved the script could
produce well-formed output and nothing about what it does with a real answer. It
now uses a multi-line value, which is the shape that actually occurs.

## Backups no longer land in the wrong place

The managed backup area could resolve to a path relative to wherever the process
was running, rather than an absolute one. In development this wrote directories
into the source tree on every test run. Your installation was not affected — it
sets an absolute path — but a module whose purpose is "every backup lands in one
managed area" should not have a way to put them somewhere else without saying so.
The area is now always absolute.
