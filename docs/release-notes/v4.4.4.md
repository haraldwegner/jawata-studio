# jawata-studio v4.4.4

**The studio no longer keeps its own copy of which engine tools exist or which of them change code: it takes both from the engine.**

## What went wrong

- **The hook's "this turn changed code" check never saw an engine tool.** It matched the engine's tool names bare (`rename_symbol`), and Claude Code writes an MCP tool into the transcript as `mcp__<server>__<tool>`. A test written before the change failed on the first engine tool it tried, `mcp__jawata-javata-dev__rename_symbol`; the match was an exact one on the bare names, so no engine tool could count under that spelling. So a turn that only refactored through `rename_symbol`, `hierarchy` or `data` was not asked for its compile gate, and the guard that refuses a write after he has been answered refused `Edit` and let the same change through an engine refactoring.
- **The lists it matched were wrong besides.** They named four tools the engine had retired (`move_method`, `move_in_hierarchy`, `replace_duplicates`, `encapsulate_field`) and left out four it publishes (`data`, `hierarchy`, `delete_anonymous_implementation`, `dependency`). The recall script's tool patterns, deployed to every Claude client, had the same stale names and the same omissions.
- **Each copy of the engine's tool names was repaired alone, after a failure showed it.** Studio 4.4.2 fixed the help, 4.4.3 the rule block and guard, engine 4.4.7 and 4.4.8 the retired-name answers. The pin that replaced the rule block's names was a 17-name list typed by hand, the fourth copy.

## What changes

- **`src-tauri/engine-surface.json` is the one copy.** It holds the engine's 44 live tools, each with the flag the engine publishes for whether it changes code, and the 65 names the engine has ever retired. The script `build/engine-surface.sh` (mode `refresh`) writes it from a running engine's `tools/list` and the engine's own record of every name it published.
- **The hook reads the engine's flag.** The stop gate and the answer-then-work guard ask whether the call is a host editing tool or an engine tool the file says changes code, under either spelling of the name. The three hand lists are gone. Two more name lists in the hook, the shapes of edit it recognises and the tools a declared failure may cite, now have a test that each names an engine tool that changes code.
- **The recall script's tool patterns are generated from the same file,** matched at the tool name rather than as a substring.
- **One test replaces the 17-name pin.** It reads the retired names from the file and fails if anything the studio writes for an agent names one: both rule blocks, ten deployed scripts, the help, the README, every seat, skill and agent file, and the hook's own source. Run against the tree before the change it named `replace_duplicates` in the recall script and four retired names in each of two hook files.
- **The release job compares the file with the published engine.** It starts the engine's jar, asks for `tools/list`, fetches the engine's record at its tag, and fails on any difference in the live tools, their flags or the retired names. A missing record, an engine that does not publish the flag or a jar that will not answer is a failure. A self-test proves the comparison fails on a flipped flag, a dropped tool, a dropped retired name and an engine without the flag.

## Behaviour that changes

- **After he has been answered, an engine refactoring call is refused in the same window and for the same reason as an `Edit`.** Before, only `Edit`, `Write`, `NotebookEdit` and `Bash` were.
- **A turn that ran a seat and changed code only through the engine is now asked for its compile gate.**

## Known limits

- **The rule block's routing table and help.md still carry tool names as prose.** They are checked against the file now; they are not generated from it.
- **Hand-written rules files outside the studio's markers are not reached,** for example a project's own CLAUDE.md. They keep whatever names their author typed.
- **The file must be refreshed at each engine release that changes the surface.** The release job fails until it is.

## Also in 4.4.4: the hook names its lanes, the duplicate gate has a way out

- **Every hook request names its lanes from one table,** and a typed message no longer asks the code lane. This is what engine 4.4.9 requires: a recall that names no lane is refused. Lane lists written in the studio's source, its seat runner, the deployed shell templates and the seat and skill texts are held to that table by a sweep that reads them; the sweep found two seat occasions the table lacked (a design question asks experience and patterns; "does something already do this" asks code) and they are now rows.
- **The duplicate gate refuses a write that adds a method** until the command carries `jawata-duplicate: <why a second implementation is right>` or `jawata-distinct: <why this is a different job>`. A write has no field for that, so a shell command carrying the declaration is recorded for the session, accepted only while a refusal is pending, and covers the next write once.

## Also in 4.4.4: the discussion is stored

- **A turn's end and each two minutes of work store the window to the engine's `transcript` lane;** a start after a compaction stores every window since the last one and brings his last words back; words attributed to him are checked once against what he wrote. A turn split by a nudge or a notification keeps the tool calls of its first window, and every read and record is held to the hook's one clock so none outlasts its four-second deadline.

## Also in 4.4.4: the observer

- **First tier, mechanical.** Three rules over each call (a foreground wait, the patch-streak gate, a habit of declared exceptions) halt a first finding once per window; the call after carries the rule as a reminder. The window is an append-only ledger that records the guard's decision. It asks the store nothing.
- **Second tier, a hired seat.** After eight calls a hired `observer` seat judges the window from a detached child no call waits for; the next call is refused once with its correction. It is off when the observer seat file says `enabled: false`. What leaves for the hired brain passes through a credential net that replaces known token formats, `NAME=value` words and long mixed runs before the brief is written.
- **Counts are readable on request and gate nothing** (`observer-kpi`, `observer-label`). Hook time per call: median 1.78 ms before, 2.85 ms with the first tier, 3.11 ms with the hired observer.

### Known limits (the observer)

- **The replay did not meet its goal.** Against six bypasses he caught, judged at the window's end, both tiers halt 3 of 6; judged at the last marked call, 5 of 6. On 195 windows with no bypass, 43 are halted (first tier 41, hired 3, one in both). The labels were made by briefed readers and checked by machine for quote exactness, not yet by him.
- Cursor and Windows were not measured, and the observer's response to a worker's calls is not decided.

## Also in 4.4.4: seats

- **The worker and the chief engineer exist as seats.** The worker declares `changes_code: true` and is the one seat hired in a write-capable mode; the studio parser reads the key as strictly as the engine does. The architect seat carries no code-changing tool, and a test holds that against the engine's own flag. The PM declares the mutation step on every code change; the test manager claims no abort signal the engine lacks.
- **A seat can declare `reads_files: true`,** and the UX seat does, so a hire of it opens the component it is asked about.
- **The `/sprint` skill says a failing test is fixed alone:** run that test until it is green, then widen to the class, the package or shard, and the suite, in that order.

Works with jawata-mcp 4.4.9.
