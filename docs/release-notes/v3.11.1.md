# jawata-studio v3.11.1

A starting fleet no longer looks broken, and a dead knowledge layer can no
longer look healthy.

## Starting up is not a failure (#16)

Every launch used to paint the tray amber for the first five minutes: the
canary asked its compiler question, the resident answered — correctly — "the
project is still loading", and the canary counted that correct answer as a
failure. Loading is now a third state. The tray keeps the brand colour, the
Field view reads "starting up", and the state is honest in both directions: a
load that *failed* still goes amber immediately, and a load that never
finishes loses the benefit of the doubt after fifteen minutes. A loading run
keeps its first timestamp across canary rounds, so the deadline is real rather
than reset by every probe.

## The canary reads the engine's new honesty

jawata-mcp v3.11.1 answers `KNOWLEDGE_UNAVAILABLE` when its store cannot be
read. The canary understands it: that answer now means NOT healthy — before
this, an error body still counted as "the store spoke", so the better the
engine reported its own trouble, the more thoroughly the dashboard hid it. An
ordinary refusal (a bad parameter) still counts as an answer, because it says
nothing about the store's health.

The canary also states its own deadline (`budget_ms`) below its transport
timeout, so a wedged store produces the typed answer it can read — not a
transport timeout racing an equal server default.

## The hooks tell the store how long they can wait

Every recall the hook sends now carries its own deadline, derived from the
hook's timeout, injected at the one seam every ask goes through so no call
site can forget it. A wedged store answers the hook inside the hook's window
instead of after it has already given up.

## Also

- The no-panics guard that scans the hook's own sources survives multi-line
  raw strings now, and a lexer desync fails the scan naming the line instead
  of silently resuming — a scanner that has lost track must say so.
- Groundwork for the recall gate ships inert (no production caller yet); it is
  not a feature of this release and is not claimed as one.
